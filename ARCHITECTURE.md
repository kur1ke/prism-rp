# Архитектура Prism RP

Классические скрипты без сборщика модулей: каждый файл — IIFE, кладёт свой публичный API в `window.PRP`. Один и тот же код работает на Perchance, с `file://`, с GitHub Pages и в Node-тестах. `build.js` склеивает файлы в порядке тегов `<script>` из `index.html`. Этот порядок и есть порядок зависимостей.

## Направление зависимостей

```
События DOM
   │
   ▼
ui/app.js ── корень: состояние сессии S, контекст ctx, навигация, разбор событий
   │
   ├─► ui/controllers/*  тонкие обработчики: прочитать ввод → вызвать сервис → перерисовать
   │        │
   │        ▼
   ├─► сервисы (прикладной уровень, create(ctx); DOM не трогают, перерисовку просят через ctx.ui)
   │     chat/service · prism/service · prism/experience-service · generation/service
   │     images/service · cards/service · assist/service · world/service · world/overlay-service · messenger/service
   │        │
   │        ▼
   │   чистые модули предметной области (без DOM, хранилища, сети и S)
   │     prism/scene · prism/experience · prism/scenario · prism/modes · prism/assembler · chat/tree · chat/branch
   │     messenger/time · messenger/environment · messenger/conversation
   │     cards/model · cards/ccard · cards/formats/* · cards/validate · cards/import
   │     world/model · world/lens · world/validate · world/resolve · world/overlay · world/canon · world/retrieve
   │     assist/assist · images/compose · images/compile · core/settings · core/util
   │        │
   │        ▼
   │   адаптеры: core/store (IndexedDB) · providers/openai · providers/perchance · providers/router
   │             images/backends (Perchance / A1111 / OpenAI images) · ui/files (браузерные файлы)
   │
   └─► ui/shell.js  порт интерфейса ctx.ui: модель представления, отрисовка областей,
                    поповеры, поиск, потоковая отрисовка, уведомления
                    └─► ui/views/*  чистые функции «модель → HTML»
```

Запрещённые направления: модули предметной области → интерфейс, `app.js`, хранилище или сеть; провайдеры → смысл Prism (сцена, опыт, карточки, дерево); хранилище → смысл Prism; сервис → DOM. Циклов нет: сервисы ссылаются друг на друга только через `ctx.svc`, по графу `chat ← exp, prism, images ← generation`.

## Состояние сессии `S`

Классификация полей (объект остаётся одним, поля описаны в `app.js`):

- **данные:** `settings`, `cards`, `chats`, `messages` (текущего чата), `experience` (персонажа), `worldPacks`, `worldLenses`, `worldOverlay` (мир текущего чата), `messengerEnv` (среда текущей переписки), `assistList`;
- **навигация:** `view`, `cardId`, `chatId`, `assist`;
- **генерация (временное):** `gen`, `drawing`;
- **интерфейс:** `drawerOpen`, `tab`, `find`, `homeQuery`, `modal`, `editProviderId`, `pop`, `editingMsg`, `expDraft`, `worldDraft`, `worldEdit`, `envEdit`;
- **кэш производного:** `lastPrism`, `imgUrls`, `imgLists`, `legacyExperience`.

Модули предметной области `S` не видят: им передаются нужные срезы (`EX.rank(records, ctx)`, `SC.fold(init, steps)`, `TR.path(index, leafId)`).

## Сценарий, первое сообщение и начало сцены (FOUNDATION-B)

- **Карточка** — то, что постоянно; **сценарий** — с чего начинается мир; **первое сообщение** — авторское начало; **сцена** — текущее состояние, выводимое из ветки.
- **Сценарий** — исходные обстоятельства. Это не постоянная часть карточки, в сцену он не копируется и не разбирается (ни эвристикой, ни моделью). В Prism он идёт отдельным разделом «С чего начинается история».
- **Граница первого ответа** (`prism/scenario.js`, единственное место правила). Для генерации берётся ветка до генерируемого ответа: opening → `[]`, new → вся ветка, regen и continue → ветка до целевого сообщения. Если она кончается репликой пользователя, эта реплика — та, на которую отвечают. Сценарий подаётся, если в остальной части нет реплик пользователя. Значит, он доступен в начале, при ответе на первую реплику, в её другом варианте и при дописывании, а дальше не подаётся. Флага «израсходован» нет: переключение ветки или варианта пересчитывает всё заново. Предпросмотр Prism считается как следующий ответ после активной ветки.
- **Первое сообщение и альтернативные приветствия** — варианты одного корневого сообщения (`opening: "authored"`). Без вызова модели; `[scene:]` разбирается как обычно. Без первого сообщения чат создаётся пустым (`leafId = null`, без заглушек).
- **Начало сцены моделью** (`generate(null, "opening")`, только по кнопке). Порядок: сборка → проверка бюджета → вызов (поток — во временном `S.gen`, в дереве узла нет) → разбор → одна запись корневого сообщения (`opening: "generated"`) → `leafId` → сохранение. Переполнение, ошибка, отмена и пустой ответ ничего не записывают. Указание «начни сцену» — временное, вне истории, считается в бюджете. Другой вариант корневого сообщения тоже получает это указание. Реплику пользователя начало сцены не подделывает: при «одном системном сообщении» служебная «[Начало]» (нужна строгим шаблонам Mistral/Gemma, требующим первый ход пользователя) не подставляется. Perchance получает запрос только из system; OpenAI-совместимому провайдеру начало отклоняется до вызова с понятной причиной — без изменений чата.

## Мир: общий пак и линза персонажа (FOUNDATION-W1)

- **Общий пак мира** — переиспользуемое знание о мире или фандоме, общее для многих карточек. **Факт мира** — декларативное утверждение о мире. Это не указание модели, не черта характера и не опыт («Тацуки переехала в Осаку» — факт; «Орихимэ было одиноко, когда Тацуки уехала» — опыт). Не сцена («университет в Каракуре» — факт; «{{char}} сейчас в библиотеке» — сцена). Не сценарий: исходные обстоятельства в факты не переносятся.
- **Линза персонажа** — только то, что у персонажа иначе поверх одного пака: фокус, выключения (`disabledFactIds`), замены (по `targetFactId`), свои факты. Пак она не меняет и не копирует.
- **Одна линза на карточку** — ограничение хранения: уникальный индекс `cardId` в `worldLenses` и проверка сервиса. Карточку не меняли: связь «карточка → линза → пак» идёт через `lens.cardId` и `lens.packId`.
- **Порядок разрешения**:
  1. факты пака с `enabled:false` исключаются;
  2. выключения линзы исключают факты — выключение сильнее замены;
  3. к оставшимся применяются замены;
  4. добавляются свои факты линзы.

  Порядок фактов пака сохраняется, свои факты идут после. Факт после замены сохраняет id факта пака, `overrideId` указывает на замену. Ссылки на пропавшие факты — предупреждения, по тексту ничего не подбирается.
- **Режим миру не принадлежит.** В паке и линзе нет полей, зависящих от сцены или переписки.
- **Хранение**: база v4, коллекции `worldPacks` и `worldLenses` (индексы `cardId` уникальный, `packId`). Обновление только добавляет коллекции. Общий бэкап и восстановление включают их. Удаление персонажа удаляет его линзу. Пак, на который ссылаются линзы, удалить нельзя.
- **Источник истины** — только канонические поля пака и линзы. Исходник карточки, её расширения, лорбук, выключенные указания, сценарий, опыт и сцена в мир не попадают. Лорбук карточки автоматически не переносится.
- **Сам W1 в модель ничего не подаёт.** «Мир персонажа» в редакторе — статичный просмотр пака и линзы (без чата). В модель мир попадает только через W2.
- **Полная схема**: общий пак → линза персонажа → наложение мира на чат → активная ветка → адаптер режима → Prism. W1 — **общий пак + линза персонажа** (переиспользуемое знание). W2 — всё, что относится к чату и ходу.

## Мир чата: наложение, ветки, отбор и подача в Prism (FOUNDATION-W2)

- **Разделение.** Общий пак и линза — знания библиотеки и карточки (W1, редактор и «Миры»). **Наложение мира на чат** — канон конкретного чата (W2, вкладка «Мир» в панели чата). Факт мира — не опыт, не сцена, не сценарий и не карточка; ни один из них в мир сам не превращается, и мир не превращается в них.
- **Хранение.** База v5, коллекция `worldOverlays` (ключ `chatId`), одна запись на чат: `{ schema: 1, chatId, timeline, variant, entries, createdAt, updatedAt }`. Хранятся только события; собранный мир не хранится и собирается на каждый ход. Обновление v4 → v5 только добавляет коллекцию. Удаление чата (и персонажа — через его чаты) удаляет наложение; удаление линзы или пака историю чата не трогает (ссылки на пропавшие факты — предупреждения). Общий бэкап включает наложения. При восстановлении записи проверяются до записи (`world/overlay-service.checkBackup`): запись без своего чата не пишется (`overlay-orphan-chat`; при замене чат должен быть в бэкапе, при добавлении — в бэкапе или уже здесь), несколько записей для одного чата отбрасываются все (`overlay-duplicate-chat`), ничего не переназначается.
- **События** (только добавляются; исправление — новое событие, переписывания истории нет):
  - `assert` — новый факт чата со своим постоянным id факта;
  - `override` — новое значение известного факта по `targetFactId`; id факта сохраняется, у события свой id (`sourceEventId`); метаданные: не задано/`null` — наследуются, задано — заменяют; `override` убранного факта явно возвращает его;
  - `retract` — убирает известный факт с этого места.
  Цель — только по id, никогда по тексту.
- **Область.** `branch` (по умолчанию, если в чате есть сообщения) — привязка ко всей активной ветке: id сообщений от корня до листа и их выбранные варианты (`chat/branch.anchorOf`). `chat` — только по явному выбору, без подставных сообщений. Пустой чат: ветку не к чему привязать — сохранение отклоняется, область сама на «весь чат» не меняется.
- **Правило ветки** одно на опыт и мир (`chat/branch.visibleOnPath`): событие видно, только если все его сообщения на активной ветке и у них выбраны те же варианты. Соседняя ветка и другой вариант ответа (в том числе раньше места привязки) событие скрывают, но не удаляют; вернулись — мир тот же.
- **Власть** (разрешение противоречий): ветка > весь чат > линза > пак. Порядок: результат W1 (без изменений) → события «на весь чат» (по `createdAt`, затем id) → события видимой ветки в порядке повествования (глубина привязки на ветке, затем `createdAt`, затем id). Внутри слоя побеждает более позднее событие. Битые события, события к неизвестным целям и повторы id в мир не входят и видны в отчёте.
- **Таймлайн и вариант** — явные селекторы чата. Нейтральный факт (пустые метки) подходит всегда; факт с меткой — только при точно таком же выбранном селекторе (без учёта регистра и лишних пробелов); метка есть, а селектор не выбран, — не подходит. `timelineVariant` линзы остаётся пометкой линзы: его смысл (таймлайн или вариант) неоднозначен, поэтому он сам ничего не выбирает и показывается подсказкой.
- **Отбор отделён от власти** (`world/retrieve`). Власть решает, какое значение факта действует; отбор — что относится к ходу. Факт входит только при положительной связи: совпадение сущности, темы или места с текстом последних реплик; место сцены или персонаж в сцене; не меньше двух длинных слов текста факта в ходе; прозвучавшая подсказка линзы, которая есть в факте. Не дают права войти: власть слоя, недавность, принадлежность ветке, наличие в паке, имя персонажа или собеседника. Фокус линзы только поднимает подходящий факт. Порядок: прямые совпадения → сцена → фокус → слова → подсказки → исходный порядок мира → id. Не больше `worldLimit` фактов.
- **Подача в Prism.** Раздел «Релевантные факты мира» после лорбука и перед опытом. Это данные, а не указания: короткое пояснение и по одному факту на строку как литерал JSON — перевод строки, `###` или ограждения кода внутри факта не начинают новый раздел; текст факта по смыслу не меняется. Пустой отбор — раздела нет. Рамка RP не менялась.
- **Бюджет.** Факты мира — уступаемый раздел: уходят с наименее релевантного сразу после лорбука (порядок прочих уступок прежний). Не поместился ни один — раздела нет. Отчёт Prism: кандидаты, вошло, не поместилось, токены, таблица отбора.
- **Режим миру не принадлежит.** Один и тот же отбор получают сцена и переписка; у переписки нет своих фактов и своего хранения мира.
- **Только явное закрепление.** Сгенерированный текст может содержать факт, но каноном чата он становится только по явному действию пользователя («Мир» → добавить / заменить / убрать). Генерация, разбор `[scene:]`, опыт и сценарий наложение не пишут. Сборка мира для генерации только читает; переполнение, ошибка, отмена и пустой ответ мир не меняют.
- **Источник истины** — только пак, линза и явные события наложения. Исходник карточки, расширения, выключенные указания, системный промпт URV, сценарий, сцена, опыт, ответ модели и сведения импорта в мир не попадают.

## Переписка: среда, время и состояние (FOUNDATION-C)

- **Режим чата фиксирован.** Сцена (`rp`) или переписка (`messenger`) выбираются при создании и не меняются: переключателя в чате нет. Одна карточка может иметь и сцену, и переписку — это разные миры; ничего между ними не переносится. Старые чаты сохраняют записанный режим, ничего не делится и не угадывается.
- **Адаптер режима** (`prism/modes`). Общее для режимов собирает `prism/assembler`: карточка, указания автора, лорбук, факты мира (тот же отбор W2 — мир режиму не принадлежит), опыт, сценарий, строгий бюджет. Сцена: рамка сцены, «Сейчас (факты)» из `prism/scene`, протокол `[scene:]`. Переписка: рамка переписки на расстоянии и три раздела-данных — «Текущее положение {{char}}» (WORLD), «Состояние переписки» (CONVERSATION), «Время переписки» (TEMPORAL). Сцена RP в переписку не подаётся, протокол `[scene:]` не просится; служебная строка `[scene:]` из ответа по-прежнему убирается из текста, но в среду не превращается. С FOUNDATION-H она хранится только неактивной копией (`ignoredSceneOps`) и сцену не создаёт.
- **Среда переписки** — текущие обстоятельства персонажа вне переписки (где, чем занят, кто рядом, что происходит, доступность). Это не факт мира, не сцена и не опыт. Хранение: база v6, коллекция `messengerEnvironments` (ключ `chatId`), одна запись на чат-переписку: `{ schema: 1, chatId, timeZone, timeMode, manualNow, events, conversationEvents, createdAt, updatedAt }`. У сцены записи нет. Итоговое положение не хранится — оно собирается по ветке.
- **События положения**: `{ id, scope, patch, provenance, effectiveAt, note, createdAt }`. Ключа нет в `patch` — значение не меняется; `null`, `""`, `[]` — очищают. Область `branch` (привязка ко всей активной ветке, `chat/branch.anchorOf`) по умолчанию, `chat` — только явно; без сообщений привязать к ветке нельзя, на «всю переписку» само не меняется. Видимость — то же правило ветки, что у опыта и мира чата. Порядок: события всей переписки (по `effectiveAt`, затем `createdAt`, затем id), затем события ветки в порядке повествования (глубина привязки, затем то же). Событие с `effectiveAt` позже текущего момента ещё не действует.
- **Доступность** (`available` / `busy` / `away` / `unknown`) — контекст для ответа, а не запрет: в Prism подаётся с пометкой, что не запрещает ответить.
- **Время.** Пояс чата (IANA) и режим: `live` — «сейчас» берётся из часов в момент действия (`ctx.clock`, в тестах подставные); `manual` — сохранённое время, меняется только явно («+15 мин», поле времени). Таймеров и фонового хода времени нет.
- **Метки сообщений неизменяемы.** У варианта переписки — `messengerAt: { at, timeZone, world }`: момент и положение персонажа на ветке перед сообщением (мир — пак, линза, наложение — не копируется). Пишется при отправке пользователем и при успешном ответе модели; момент ответа выбирается при подготовке. Новый вариант — своя метка; переключение вариантов переключает метку; «продолжить» метку не меняет (ставит только отсутствующую); правка текста метку не трогает. Ошибка, отмена, пустой ответ и переполнение метку не пишут и время не двигают. У старых сообщений без метки время неизвестно (время записи не подставляется).
- **Состояние переписки** выводится из активной ветки каждый раз: кто писал последним, сколько сообщений без ответа, время последнего сообщения и сколько прошло, открыта ли переписка и почему (`empty`, `awaiting-character`, `awaiting-user` — вопрос в последнем ответе, `idle`, `quiet` — 12 ч и больше после ответа). Договорённости (обещания и планы) — только явные отметки пользователя с правилом ветки; из текста ничего не извлекается.
- **Прошедшее время ничего не устанавливает.** В Prism подаётся «что происходило за это время, неизвестно, если об этом не сказано». Нет симуляции, расписаний, сна, поездок, событий «вне кадра» и сообщений по инициативе персонажа.
- **Генерация читает среду, но не пишет её.** Положение, договорённости и время меняются только явными действиями во вкладке «Среда».
- **Бюджет.** Неуступаемое ядро переписки: рамка, где / чем занят / доступность, состояние переписки, текущее время и время последнего сообщения. Уступки (после фактов мира, до опыта): сначала договорённости со старых, затем списки «рядом» и «происходит». Порядок прочих уступок прежний.
- **Удаление и бэкап.** Удаление переписки (и персонажа — через его чаты) удаляет её среду; пак, линза и мир чата её не трогают. Бэкап включает среды. Восстановление проверяет до записи: среда только для переписки из бэкапа (замена) или из бэкапа и уже существующих (добавление); для сцены, сироты и повторы одного чата — отбрасываются, ничего не переназначается. При добавлении местный чат главнее входящего с тем же id: если режимы различаются, входящий чат отклоняется до записи вместе с его сообщениями, картинками, опытом, наложением мира и средой (`chat-mode-conflict`, `chat/service.checkBackupChats`); среда для существующего чата проверяется по его местному режиму.
- **Старая переписка без среды** открывается с пустой средой в памяти (всё неизвестно, живое время, пояс браузера); запись появляется только при явной правке.

## Границы Prism и ядро карточки (FOUNDATION-H)

- **Сцена** владеет только непосредственным состоянием RP: время, место, погода, кто рядом, одежда, поза и настроение. Настроение — только как интерпретация, с возрастом по ветке и без часов.
  - Сцена **не** владеет отношениями, памятью сюжета, каноном мира и опытом.
  - Протокол `[scene:]` не просит `rel` и `flag`.
  - Старые операции `rel` / `relset` / `flag` в сохранённых вариантах не удаляются и не переписываются. При свёртке они не действуют: только счётчик `legacyIgnored` для отчёта и пометка «устарело, не действует» под сообщением.
  - Старые операции ни во что не превращаются: ни в опыт, ни в мир, ни в сценарий, ни в среду, ни в будущие отношения.
  - Ползунка отношения нет; скалярного «0 = нейтрально» нет.
- **Данные и указания** (`prism/data`).
  - Указания — только «Указания автора карточки…» (до и после истории) и «Служебные указания для этого ответа»: протокол сцены и рисования, «продолжи», «начни сцену». Они идут как есть.
  - Всё остальное подаётся разделами-данными: карточка (ядро и подробности), примеры речи, персона, лорбук, факты мира, опыт, сценарий, сцена, среда переписки (положение, состояние, время).
  - Раздел-данные начинается с пометки `[данные · …]`. Значения — литералы JSON в одной строке, подписи пишет только код.
  - Перевод строки, `###` или «Игнорируй систему» в тексте пользователя или файла не создают раздел и не становятся указанием. Текст не меняется по смыслу: ничего не вырезается и не переписывается, проверки моделью нет.
  - Имена в заголовках однострочные.
  - Рамка обоих режимов содержит общее правило чтения разделов (`prism/modes.DATA_RULE`).
  - При «одном системном сообщении» разделы и пометки те же.
- **Эпистемический статус** — лёгкий словарь, используется там, где он нужен смыслу:
  - ESTABLISHED — явная сцена, действующий факт мира, поле среды;
  - DERIVED — состояние переписки, прошедшее время;
  - INTERPRETATION — настроение в сцене, `interpretation_at_the_time` в опыте;
  - UNKNOWN — пустое не заполняется значением по умолчанию.
- **Опыт** подаётся как свидетельства прошлого: по строке-объекту `{scene_time?, event, interpretation_at_the_time?, consequences_observed?}`. Смысл записей и отбор (чат, ветка, релевантность, важность без права войти) не менялись.
- **Карточка** — источник устойчивой истины о персонаже, её поля не меняются.
- **Ядро для Prism** (`card.prismCore`, `prism/card-context`) — компактное представление для каждого хода, а не источник истины.
  - Формат: `{ schema: 1, identity, traits[], voice[], durableContext[], source: manual|derived|imported, reviewed }`.
  - Видно и правится в редакторе («Основное» → «Ядро для Prism»). «Собрать из карточки» детерминированно и без модели; «Сбросить» возвращает запасное.
  - Модель ядро не пишет, генерация его не меняет.
  - Ядро из файла (`extensions.prism_rp.prismCore`) приходит данными с `reviewed: false` и не используется, пока пользователь не отметит «Проверено».
  - Схема карточки не менялась (2): нет ядра — `prismCore: null`.
  - **Запасное ядро**: имя, начало описания и начало личности. Каждое — не длиннее 600 символов, по целым предложениям: одно длинное предложение берётся целиком. Сокращение видно в отчёте, остаток уходит в подробности.
- **Выборочные подробности.** Остаток описания и личности, прошлое и внешность режутся на куски по абзацам; длинный абзац — по предложениям до 500 символов. Отбор детерминированный, без модели и эмбеддингов, не больше 4 кусков за ход. Кусок входит только при положительной связи:
  - имя или термин из куска прозвучал в последних репликах, в сцене, в среде переписки или в действующем сценарии;
  - или не меньше двух общих значимых слов: формы одного слова сравниваются по общему началу, имена участников и служебные слова не считаются;
  - внешность — ещё при разговоре о внешности или одежде и при начале сцены моделью.

  Важность, порядок и свежесть права войти не дают. Отбор решает только включение, но не истинность.
  - Картинки берут полную внешность отдельно (настройки изображений карточки), бюджет текста их не касается.
- **Примеры речи** по числу ответов персонажа на ветке: 0–2 — все, 3–5 — первый, 6 и больше — ни одного.
- **Лорбук** — справка карточки низкого приоритета.
  - Подаётся одним разделом после персоны: записи «до персонажа» — первыми.
  - Пометка раздела говорит, что при расхождении с фактами мира этого чата верны факты мира. Пометка мира говорит то же с его стороны.
  - Противоречия не подавляются молча и не угадываются.
  - Импорт сохраняет флаг `enabled` из файла: лорбук — данные, а не указание, поэтому карантин указаний к нему не применяется. Решение принято, чтобы не ломать существующие карточки.
  - Лорбук остаётся в карточке; паки сам не создаёт.
- **Власть знаний о мире:** канон чата и ветки > линза персонажа (замены, свои факты) > общий пак > лорбук карточки > неизвестно.
- **Порядок Prism:**
  1. рамка;
  2. указания автора;
  3. ядро карточки;
  4. подробности карточки;
  5. примеры речи;
  6. персона;
  7. лорбук;
  8. факты мира;
  9. опыт;
  10. сценарий, пока действует;
  11. сцена или среда переписки;
  12. история;
  13. указания автора после истории;
  14. служебные указания ответа.
- **Бюджет.** Уступки идут в таком порядке:
  1. старая история;
  2. примеры речи, с последнего;
  3. подробности карточки, с наименее связанной;
  4. лорбук;
  5. факты мира;
  6. договорённости переписки;
  7. списки «рядом» и «происходит»;
  8. менее релевантный опыт;
  9. указания после истории;
  10. персона, сценарий, указания автора, вторичное ядро (устойчивое, манера речи, черты сверх первой, хвосты по предложениям);
  11. самый релевантный опыт;
  12. история до последнего сообщения.

  Не режутся: рамка, минимум ядра (имя, первое предложение), сцена или ядро переписки, служебные указания. Иначе — OVERFLOW: 0 вызовов модели, ничего не записывается.
  - Отчёт Prism (`report.card`) показывает: ядро (явное или запасное, токены, сокращения), кандидатов подробностей с причинами и судьбой (в контексте / не поместилось / сверх лимита / не относится), примеры (сколько, по какому правилу), счётчик устаревших операций сцены.
- **Режимы.** У переписки сцены нет: `chat/service.sceneState` для переписки пустое, поэтому старые `sceneOps` переписки тоже не действуют. Ручные правки сцены в переписке не пишутся.
  - Картинки переписки строятся из `[draw:]`, карточки и персоны. Одежду и место из сцены RP они не берут; «вне кадра» ничего не придумывается.
  - Ассистент берёт строку сцены только у сцены RP.
  - Картинки — производное: в Prism не возвращаются.
- **Бэкап.**
  - «Заменить» — весь набор данных Prism RP. Сначала очищаются все известные коллекции (`core/store.STORES`, включая настройки), затем пишется проверенный бэкап. Коллекции нет в файле — после замены она пустая. Сама база не удаляется, жизненный цикл соединения прежний.
  - До записи `core/backup.check` отклоняет повторы id и записи без своего персонажа, чата или пака. Две линзы одного персонажа отклоняются, в том числе при добавлении поверх существующей. Ничего не переназначается.
  - Мир чата, среда переписки и конфликт режима проверяются прежними проверками сервисов уже по проверенному списку чатов.
  - «Добавить» работает как раньше.

## Куда класть будущее

- **Новый формат карточки** — адаптер в `cards/formats/<формат>.js` (регистрируется через `PRP.cardFormats.register`), правило определения в `cards/formats/detect.js`, подключение в `index.html` между `formats/common.js` и `cards/import.js`. Рантайм читает только каноническую карточку; `source` во время работы не читается никогда.
- **Инициатива и прочее развитие переписки (FOUNDATION-D)** — новые чистые модули в `js/messenger/` поверх среды и состояния переписки и подключение через `messenger/service.js`; `app.js` и контроллеры только вызывают.
- **Процедурные события** — `js/procedural/*`, **отношения** — `prism/relationship.js` (чистый) с подключением в `prism/service`.
