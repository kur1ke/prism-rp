# Prism RP 0.5.0

Среда для ролевой игры, где персонаж реагирует на сцену через стабильную личность (Card) и пережитый опыт (Experience). Ни один из этих слоёв не становится жёстким сценарием. Рутину — время, место, одежду — ведёт приложение.

Спецификация: документ «Prism RP — спецификация v1».

## Что нового (testing) — PERF-01: можно писать сразу после ответа

- Ответ персонажа больше не держит поле ввода, пока идёт служебный разбор состояния (до 20 с). Следующую реплику можно отправить сразу.
- Если разбор ещё идёт, над полем видно «Разбираю предыдущий ответ — сообщение отправится автоматически» и кнопка «Отменить». Реплика уходит сама, как только разбор закончится. Следующий ответ модели по-прежнему строится на полном состоянии.
- Если за это время сменились чат, ветка, вариант ответа или текст сообщения в истории, реплика не отправляется: текст возвращается в поле ввода своего чата.
- У каждого чата своё поле ввода: недописанный текст не переезжает в другой чат и ждёт при возвращении.
- Режим разработчика: Debug → «Тайминги» — длительности разбора, запроса к модели, подготовки картинки и «ответ показан → можно писать».

## PERF-02A — отдельная модель обработки (эксперимент)

В «Настройки → Модели» можно выбрать **модель обработки** независимо от модели персонажа. RP-модель продолжает писать реплики, Processing Provider обслуживает StateTracker и подготовку промптов изображений. По умолчанию выбрано «Как у персонажа», поэтому старые настройки работают без изменений. Если выбранный обработчик недоступен, используется RP-модель с предупреждением в настройках.

Это **маршрутизация**, а не параллельный конвейер: обязательный анализ состояния по-прежнему завершается до следующего RP-запроса. Сокращение задержки не заявляется без отдельного измерения.

## Что нового — FOUNDATION-D: «Проверить инициативу» в переписке

- В переписке у поля ввода есть кнопка **«Проверить инициативу»**. Она спрашивает модель, написал(а) бы персонаж вам сейчас сам(а).
- Персонаж может написать или промолчать. Если промолчит, появится уведомление «Персонаж решил пока не писать», и ничего не сохранится.
- Учитывается известное: характер, опыт, мир, среда, время переписки, ваши открытые договорённости и долгое молчание (12 ч и больше). Время и договорённости — поводы, а не приказ.
- Сообщение, написанное первым, сохраняется как обычное, с пометкой «первым» у времени. Его можно перегенерировать, продолжить или удалить. Второе такое сообщение подряд, без вашего ответа, не создаётся.
- Ничего не происходит само: нет таймеров, фоновых сообщений и уведомлений. В сцене (RP) кнопки нет.
- В режиме «Одно системное сообщение» у OpenAI-совместимых моделей проверка недоступна: строгому шаблону нужна ваша реплика последней, а подделывать её Prism не будет. Через Perchance проверка работает.

## Что изменилось — FOUNDATION-H: границы Prism и ядро карточки

- **Сцена — только «здесь и сейчас».** Время, место, погода, кто рядом, одежда, поза и настроение. Ползунка «Как относится к вам» больше нет, и отметки сюжета (`flag`) больше не ведутся. Старые отметки отношения и сюжета в сообщениях сохранены как были, но не действуют: в модель они не подаются, под сообщением помечены «устарело, не действует».
- **Настроение — оценка, а не факт.** Модель видит его как предполагаемую оценку с возрастом по ветке.
- **Данные отдельно от указаний.** Указания — только указания автора карточки и служебные указания для текущего ответа. Описание, личность, персона, сценарий, лорбук, опыт, сцена, мир и среда переписки подаются как данные в кавычках. Текст вида «### Указания автора» внутри карточки не становится указанием и не меняется.
- **Лорбук — справка карточки.** Он подаётся как сведения ниже по власти, чем факты мира этого чата: при расхождении верны факты мира. Включённые в файле записи по-прежнему включены.
- **Ядро для Prism.** В редакторе персонажа, раздел «Основное», есть блок «Ядро для Prism»: кто это, черты, манера речи, устойчивое. Оно подаётся на каждом ходе. Без ядра Prism берёт начало описания и личности по целым предложениям. Кнопка «Собрать из карточки» заполняет ядро из полей без вызова модели, «Сбросить» возвращает автоматический вариант. Поля карточки не меняются.
- **Подробности по ходу разговора.** Прошлое, внешность и остаток описания подаются, только когда относятся к разговору. Внешность подаётся и при начале сцены моделью. Примеры речи подаются целиком в начале чата, один пример — при 3–5 ответах персонажа и ни одного — дальше. Во вкладке Prism видно, что вошло и почему.
- **«Заменить бэкапом» заменяет всё.** Всё, чего нет в файле бэкапа, удаляется, включая настройки, которые возвращаются к значениям по умолчанию. Записи бэкапа без своего персонажа или чата и повторы id не восстанавливаются, о них сообщает уведомление. «Добавить» работает как раньше.

## Что нового в 0.5.0 — этап 1: причинный фундамент

**Каждый чат — свой мир.**
- Опыт принадлежит чату (`experience.chatId`). Другой чат с той же карточкой его не видит, сцена и переписка — разные миры.
- При удалении чата удаляется и его опыт.

**Опыт подчиняется веткам, как сцена.**
- Запись из сообщения видна, только пока это сообщение (и тот же вариант ответа) лежит на активном пути.
- Запись, добавленная вручную, видна во всех ветках своего чата.
- Скрытые записи не удаляются: вернулись в ветку — запись вернулась.

**Старые записи не угадываются.**
- Чат берётся из `source.chatId` или из сообщений, если все они из одного чата.
- Иначе запись попадает в раздел «Без привязки к чату»: хранится целиком, в модель не идёт, привязывается вручную.
- Миграция идемпотентна.

**Отбор опыта: тема → участники → важность → свежесть (только при равенстве).**
- Противовес по противоположному знаку убран.
- Входит только запись, совпавшая по теме: важность упорядочивает подходящие, но не делает запись подходящей.
- Имена участников не считаются совпадением темы.
- Во вкладке Prism есть таблица отбора.

**Настроение** подаётся с возрастом по активной ветке: «подавлена — отмечено 10 ходов назад».

**Указания автора карточки** (system_prompt, post_history_instructions) подаются отдельно от склонностей. Настройка «Не передавать инструкции после истории» по умолчанию выключена.

**Строгий бюджет контекста.**
- Итог не превышает бюджет.
- Если не помещается, уступают по порядку:
  1. старая история;
  2. примеры речи;
  3. лорбук;
  4. менее релевантный опыт;
  5. указания после истории;
  6. персона, сценарий, указания автора, хвост описания (по абзацам и предложениям);
  7. самый релевантный опыт;
  8. история до последнего сообщения.
- Рамка, сцена и протокол не режутся. Если и они не помещаются — явное «не помещается»: запрос не отправляется, дерево сообщений не меняется (ни нового ответа, ни варианта, ни правки).

**Итоговый порядок контекста:**
- system: рамка → указания автора → лорбук «до персонажа» → карточка (склонности) → примеры речи → персона → лорбук → опыт → сцена;
- история (user / assistant);
- system: указания автора после истории → протокол сцены и рисования.

При «одном системном сообщении» служебное идёт одним system в начале.

## Что было в 0.4.0 — Ассистент

Раздел **«Ассистент»** в меню слева — разговор с самой моделью вне ролевой игры. Здесь модель — помощник автора, а не персонаж.
- **О чём спросить:** совет по карточке, придумать персонажа или приветствие, разобрать, почему персонаж ведёт себя так, подобрать теги для картинок или настройки модели.
- **Контекст по выбору:** кнопка в шапке подключает карточку персонажа и, если нужно, выдержку из его чата с текущей сценой. Из чата: меню «⋯ → Спросить ассистента об этом чате».
- **Ответы:**
  - оформление списками, заголовками и блоками кода;
  - кнопки «Скопировать», «Другой ответ», «Изменить» (вернуть вопрос в поле ввода).
- **Разговоры:** сохраняются и попадают в бэкап; список — по кнопке с часами.
- **Модель та же,** что выбрана для игры: бесплатная Perchance или ваш API.
- **Поведение ассистента** можно поменять: «Настройки → Генерация → Инструкция ассистента».

**Когда рисовать.** Модель сама решает, когда показать картинку: пишет служебную строку `[draw: …]`, приложение её прячет и рисует сразу. Кнопка «Нарисовать» под любым ответом рисует этот момент вручную.

**Как собирается промпт.** Логика ваших модулей из форка перенесена и переписана под новую архитектуру:

- Чистка промпта: повторы с триггером, лишние запятые, `solo` при двух людях.

**У картинки:**

**Персонаж и вы.**
- В карточке появился раздел «Изображения»: триггер, другие имена, стилевые теги, негатив, LoRA, seed, внешность, гардероб, откровенные модификаторы.
- В разделе «Вы»: ваша внешность для картинок и выбор «со стороны / от первого лица».

### Подключение Forge / A1111

1. Запустите сервер с флагами `--api --cors-allow-origins=*`. Можно указать точный адрес вместо `*`: приложение показывает его в подсказке под полем адреса.
2. «Настройки → Изображения → Forge / A1111 / ReForge», адрес `http://127.0.0.1:7860`.
3. Нажмите «Проверить и загрузить списки» и выберите модель.

Браузер может спросить разрешение на доступ к локальной сети — разрешите. Если сервер занят (например, обучением LoRA), запрос вернёт ошибку. Приложение покажет её и не будет повторять запрос: сервер мог уже начать рисовать.

В редакторе персонажа виден итоговый «мир персонажа». Импорт и экспорт паков — собственный JSON. В контекст модели мир пока не подаётся.
- **Провайдеры**:
  - бесплатная модель Perchance (ai-text-plugin);
  - любые OpenAI-совместимые API (OpenRouter, DeepSeek и др.);
  - локальные LM Studio / Ollama / llama.cpp / KoboldCpp — работают в отдельной версии. На Perchance они станут доступны только при включённом на сервере CORS.
- **Бэкап**: один JSON со всеми данными. Через него же делается переезд. «Заменить» заменяет весь набор данных: всё, чего нет в файле, удаляется. «Добавить» дописывает к существующему.

## Установка на Perchance

Ставьте Prism RP в **новый** генератор, а не в форк URV, иначе код форка затрётся.

1. Войдите на perchance.org (кнопка `login` справа вверху) и нажмите `+ new` слева вверху.
2. **Верхнее левое окно с кодом** (поле Lists — там пишутся строки вида `{import:…}`): выделите всё (Ctrl+A) и вставьте содержимое `dist/perchance/lists.txt`.
3. **Нижнее правое окно с кодом** (поле HTML, под окном предпросмотра): выделите всё и вставьте содержимое `dist/perchance/html.html`.
4. Нажмите `save` справа вверху. Приложение появится в окне предпросмотра; бесплатная модель Perchance выбрана сразу.

Чат «AI helper» в левой колонке редактора для установки не нужен.

Код внутри `<script>` и `<style>` Perchance не обрабатывает. Сборка дополнительно проверяет, что в разметке вне них нет `[ ] { }`. Инструкция в ai-text-plugin передаётся функцией, поэтому скобки в карточках и сообщениях не раскрываются.

## Отдельная версия (для переезда)

`dist/standalone/index.html` — один файл, открывается двойным щелчком или с любого статического хостинга. Это тот же код, только без провайдера Perchance.

**Переезд**: на Perchance «Настройки → Скачать бэкап», в новой среде «Загрузить бэкап». Данные хранятся в IndexedDB того сайта, где открыто приложение, поэтому бэкап — единственный мост между платформами.

## Разработка

```
node tests/run.js                 # 80 юнит-тестов чистых модулей
node build.js                     # сборка dist/perchance и dist/standalone
python3 tests/e2e.py <папка>      # 103 сквозные проверки (с моком Forge/A1111) в headless Chromium (нужен playwright)
```

Исходники — классические скрипты без сборщика. Каждый модуль кладёт себя в `window.PRP`, поэтому один и тот же код работает на Perchance, с `file://` и в Node-тестах.

Устройство модулей, направление зависимостей и владение — в [ARCHITECTURE.md](ARCHITECTURE.md). Коротко:

- **чистые модули предметной области:** `prism/*`, `chat/tree`, `cards/*` (модель, форматы, проверка, импорт), `assist/assist`, `images/compose`, `images/compile`, `core/settings`;
- **прикладные сервисы:** `*/service.js`, `prism/experience-service.js`;
- **адаптеры:** `core/store`, `providers/*`, `images/backends`, `ui/files`;
- **интерфейс:** `ui/views/*` (разметка), `ui/shell.js` (отрисовка), `ui/controllers/*` (события), `ui/app.js` (корень).

Привязка к Perchance — один файл-адаптер плюс одна строка импорта в Lists. Всё остальное переезжает без изменений.

Шрифты подгружаются с Google Fonts; без сети используются системные шрифты.
