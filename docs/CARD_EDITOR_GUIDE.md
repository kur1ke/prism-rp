# PRISM-RP — памятка по карточкам персонажей

**Для пользователей и AI-ассистентов, редактирующих карточки.**
Это **отдельный файл документации**, не содержимое карточки и не инструкция RP-модели. Полную техническую таблицу соответствий см. в `CARD_FORMAT_COMPATIBILITY.md`.

## Что куда писать

| Поле редактора | Содержание | Не путать с |
| --- | --- | --- |
| Имя | Имя персонажа | псевдонимы для изображения |
| Описание | Кто персонаж, роль, устойчивые обстоятельства | внешность, подробная биография и текущая сцена |
| Внешность | Телосложение, черты лица, волосы, приметы, татуировки | теги SDXL и рекомендации LoRA |
| Личность | Характер, темперамент, манера общения, предпочтения | системные команды |
| Прошлое | Биография и значимые произошедшие события | действующее время/место |
| Сценарий | Начальные обстоятельства истории | непрерывно обновляемое состояние сцены |
| Приветствие | Первое сообщение персонажа | установленные навсегда факты |
| Примеры диалога | Образцы манеры речи | обязательный сюжет |
| Лорбук | Справочные знания и правила активации по ключевым словам | произвольные системные инструкции |
| Пользовательские поля | Дополнительные сведения определённой категории | неявные команды модели |
| Изображение → Базовая генерация | Теги визуального генератора, гардероб, негатив, seed | обычное текстовое описание внешности |
| Изображение → LoRA | Имя сети, вес, триггер и опциональные правила тегов | канонические физические свойства героя |

**Пример:** В «Описание» — «Лилит — студентка и девушка-кошка, интересуется ИИ». В «Внешность» — «серо-зелёные глаза, бордовые волосы, чёрные кошачьи ушки». В «Изображения» — `gray-green eyes, burgundy hair, black cat ears`.

## Настройки изображений

«Базовая генерация» и «LoRA» находятся внутри **одной** вкладки «Изображения» и раскрываются независимо. LoRA не обязательна. Триггер LoRA задавайте точным словом автора (например, `lilithx`), а дополнительные ассоциированные теги включайте только при необходимости. Наличие тега у автора ещё не доказывает, что он является обязательным триггером.

Включённая галочка **«Продвинутый режим»** разрешает дополнительные правила LoRA; выключенная **сохраняет текст, но полностью отключает применение правил**. Другие основные настройки остаются активны. Не подменяйте текущую одежду героя нарядом из коллекции только потому, что он часто встречался в обучении LoRA.

## Пользовательские поля

Дополнительное поле состоит из названия, содержания, режима включения и **отдельной галочки «Передавать модели как данные»**.

- Выключенное поле сохраняется, но не поступает RP-модели.
- Включённое поле добавляется как обычная справочная информация, с учётом связи с разговором и доступного бюджета контекста.
- Режим «Всегда» означает приоритетный отбор, **не обход бюджета**.
- Поля, полученные при импорте файла, изначально выключены, даже если в источнике помечены включёнными. Проверьте перед активацией.
- Незнакомые простые поля сторонних карточек, похожие на сведения о персонаже, предлагаются в пользовательских полях. Технические объекты, параметры, пароли и инструкции не переносятся туда автоматически.
- Галочка «Подробнее» у пользовательского поля показывает исходный формат и путь, а также режим передачи. Она не включает отправку модели и не изменяет содержимое. При выключении эти сведения скрыты, но сохраняются.

Не используйте пользовательские поля для скрытых системных указаний. Явные авторские инструкции имеют собственные отдельные настройки и границу доверия.

## Обмен файлами и совместимость

Базовый экспорт — стандартная Character Card V3 с пространством `extensions.prism_rp`. В нём хранятся раздельные `description`, `appearance`, `background`, настройки изображений и пользовательские поля. Декларированные поля остаются присутствующими даже когда пустые (строка `""`, массив `[]`).

V3 **не стандартизует** самостоятельное `appearance`. Поэтому PRISM-RP добавляет к стандартному `data.description` отдельные именованные абзацы «Внешность» и «Прошлое» для сторонних приложений, а оригинальные отдельные значения сохраняет в `extensions.prism_rp.fields` для обратного переноса. Если другие программы изменили `description`, убедитесь, что смысл полей остался согласованным.

Незнакомые поля и расширения сохраняйте без удаления, не объявляйте их автоматически инструкциями. Если семантическое соответствие неизвестно — отразите это в отчёте преобразования, а не угадывайте.

## Для AI-редактора карточки

Сначала установите исходный формат и конкретное значение его ключей. Редактируйте только запрошенные пользователем поля. Не смешивайте внешность с описанием, личность с системными командами, биографию со сценарием, а теги LoRA с каноном персонажа.

Сохраняйте точные имена LoRA, триггеры, веса, макросы `{{char}}` и `{{user}}` и неподдерживаемые расширения. Не делайте пустое поле отсутствующим и не выдумывайте недостающие факты. После изменения проверьте JSON, типы, обратный импорт и совпадение объединённого `data.description` с раздельными полями. Любые неуверенные преобразования отметьте отдельно.

**Эта памятка предназначена для чтения при редактировании файла. Её нельзя копировать в `system_prompt`, `description`, `character_book` или другие поля, уходящие игровой модели.**
