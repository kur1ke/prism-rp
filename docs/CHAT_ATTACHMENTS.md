# Вложения в чат — тестовый этап

- В обоих режимах (сцена/переписка) кнопка «Файл» позволяет выбрать до 4 файлов по 2 МиБ каждый; можно отправить сообщение без текста.
- Файлы входят в выбранный свайп пользовательского сообщения (`swipes[].attachments`). В объекте: `name, kind, mime, size, dataUrl`; у текстовых документов дополнительно `excerpt, truncated`.
- Поддерживается передача текста из `.txt, .md, .csv, .tsv, .json, .log, .yml, .yaml, .xml, .ini`. В модель передаются только первые 12 000 символов каждого такого файла; из остальных типов модель получает лишь уведомление об имени и том, что содержимое недоступно.
- JPG/PNG/WEBP/GIF, PDF и другие файлы можно прикрепить и скачать из истории, **но они не передаются модели как изображение/PDF и не анализируются моделью**. Никакого vision/PDF API сейчас нет. Названия не считаются доказательством содержания.
- Оригинал локально хранится как Data URL в IndexedDB. Это увеличивает размеры резервных JSON-копий. Ничего не загружается на сервер ради хранения; текстовый отрывок уходит текущему провайдеру LLM в составе обычной истории.
- Текст файла — данные внутри пользовательского сообщения, не system/author directive. Данные проходят обычный строгий бюджет Prism; при переполнении действуют штатные degradation/OVERFLOW.
- Файлы неотправленного сообщения сохраняются **только на время открытой страницы** (отдельно для каждого чата). Отмена ожидающей отправки оставляет вложения в черновике; успешная отправка переносит файлы в свайп. Старые записи без поля `attachments` корректно работают.
- Удаление сообщения/ветки/чата удаляет соответствующие вложения вместе с сообщениями. При экспорте чата в TXT сохраняются имена, а не байты; полноценный JSON-бэкап включает содержимое.

## Проверка в тестовом зеркале

1. Открыть сцену и переписку, прикрепить TXT+PNG, удалить один файл из черновика, отправить сообщение только с TXT.
2. Проверить, что сообщение и файл видны; TXT влияет на ответ модели, а изображение не воспринимается ею как просмотренное. Проверить скачивание байт без потерь.
3. Обновить вкладку и проверить историю/скачивание; сделать JSON-бэкап и восстановление.
4. Переключить ветку/свайп и убедиться, что видны только соответствующие вложения.
5. Проверить неверный файл >2 МиБ, более 4 файлов, файл с опасными символами в имени, отмену ожидающей отправки.
6. Проверить строгий контекст и отказ preflight на длинных TXT (без нового узла модели при отказе), отправку в Perchance и через OpenAI-совместимый провайдер.
7. Убедиться, что используется IndexedDB `prism-rp-testing`, загрузчик тестового зеркала получил нужный SHA, а продакшен не изменился.

**Статус:** проверка живого Perchance и браузерный E2E не выполнены в рамках подготовки PR; для выхода в main нужны ручные проверки.
