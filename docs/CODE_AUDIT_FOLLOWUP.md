## A01: условное изменение актуальной записи

Observer больше не сохраняет полную ранее подготовленную копию сообщения. Одна `readModifyWrite`-транзакция читает исходный путь, сверяет текст, родительские связи, выбранные свайпы, DRAW и поля состояния и меняет только `stateEvents`, `wearInquiries`, `stateStatus` целевого свайпа. Картинки и прочие свежие поля сохраняются. Изменённый/удалённый источник даёт `stale-branch`; запись не выполняется.

Начало рисования тоже добавляет/заменяет только свою image-entry в актуальной записи. Удалённые сообщение или картинка не восстанавливаются; конкурирующая перерисовка не перезаписывается. Подготовленное состояние показывается только после успешной транзакции. Для авторского DRAW используются его собственные исходники, для остальных изображений — исходное состояние, как при финальном image commit.

Модель событий, правила извлечения, инструкции RP, бюджет, схема IndexedDB v8 и остальные пункты аудита не меняются. Это не обещание атомарности всех других операций записи сообщений.

Регрессия `tests/e2e-observer-image-race.py`: до исправления падает на `observer-last: image lost`; после проверяет два порядка записи, сохранение постороннего поля, удаление источника перед записью Observer/изображения, правку текста/предка другим writer, обычную картинку из текста без DRAW и reload. RP/Messenger × 1440/390, девять случаев на сочетание. Внешние модели и image backend подменены; записи и транзакции — настоящий IndexedDB.

F20/F21 и полный источник Observer продолжают проверять отказ записи и финальную атомарность. Их тестовые перехватчики различают начальную и финальную транзакции. Фикстура продолжения сохраняет изменённый текст/DRAW перед запуском Observer, как production-путь.
