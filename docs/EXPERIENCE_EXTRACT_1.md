# EXPERIENCE-EXTRACT-1 — экспериментальный extractor значимых эпизодов

**Статус:** EXPERIMENT, implementation candidate on feature branch; live RP model validation **NOT RUN**.  
**Основа:** [CHARACTER_CORE_EXPERIENCE_FOUNDATION.md](CHARACTER_CORE_EXPERIENCE_FOUNDATION.md) и этап 5 [PRISM_URV_IMPROVEMENT_ROADMAP.md](PRISM_URV_IMPROVEMENT_ROADMAP.md). В URV-аудите отмечалась пакетная экстракция эпизодов; здесь самостоятельная реализация с собственным provenance, без переноса кода URV.

## Назначение и границы

Это **извлечение кандидатов** из текущей истории, а не полноценная память и не её семантический retrieval. Во вкладке **Опыт** пользователь нажимает **«Найти эпизоды»** (название действия общее для Scene и Messenger). Модель получает последние **16 сообщений активной ветки** (до 520 символов доступного текста на сообщение) с их source IDs и ролями. В отличие от обычного RP-запроса, Card, Core, lorebook, Scene, World, сохранённые Experience и Author Directives сюда не подаются. Один отдельный запрос **только по явному действию пользователя**. Источник представлен JSON-данными; текст не наделяется инструктивной властью.

Модель предлагает до 4 событий с `messageId`, дословной `quote`, `event`, необязательными `interpretation / consequences / domains / aboutUser`. Парсер отвергает придуманные ID и цитаты, отсутствие валидного JSON, слишком большой или неверный формат и повторы внутри ответа. **Дословная цитата не доказывает истинность предложенного пересказа.** Поэтому предложения находятся только в памяти интерфейса и не участвуют в следующем RP-запросе, пока пользователь не откроет форму, не проверит и не сохранит каждое.

Произведённая запись сохраняет `source.messageIds`, `source.swipes`, `source.textHashes`, `source.ancestryHash`, `source.evidence` и `source.proposedBy` в уже существующей коллекции Experience (нового storage schema нет). Для новых записей из сообщения, в том числе добавленных вручную кнопкой «В опыт», теперь сохраняется отпечаток текста исходного свайпа. `Experience.visibility` запрещает показывать такую запись после изменения текста без смены ID / свайпа **или изменения выбранного свайпа любого предка источника**. Отпечаток префикса пути вычисляется детерминированно; изменение контекста источника не трактуется как тот же самый пережитый эпизод. Неподтверждённые кандидаты не сохраняются, импорт не превращается в instructions или активную память.

## Поведенческие ожидания

- В Scene модель может описывать действия персонажа, в Messenger — сообщения и заявленные обстоятельства; extractor не превращает автоматически заявления в установленный канон.
- Обычная смена ветки, свайпа, сообщения или чата между извлечением и подтверждением делает временные результаты недействительными для записи.
- Отсутствие подходящего эпизода — пустой список без записи, а не синтетическое событие.
- Рутинная одежда и намерения не должны становиться долговременной личностью. Это **инструкция модели**, а не гарантия парсера; требуется живая оценка точности.
- Source fingerprint не является криптографической подписью или семантической проверкой правдивости. Ручная правка текста предложенного `event` также остаётся ответственностью пользователя.
- Проверка бюджета отдельного запроса проводится до обращения к провайдеру; если не помещается, вызов не происходит. Принцип OVERFLOW не ослабляется.
- Обнаружение может стоить дополнительного вызова текстовой модели; обычные ответы RP дополнительные вызовы extractor не делают.

## Не входит

Автоматическое извлечение после каждого сообщения, фоновая обработка, автоматическое сохранение, дедупликация **между** ранее сохранёнными записями, пересмотр убеждений, семантический retrieval и изменение Core. Ручные chat-wide записи без источника продолжают иметь прежнюю семантику. Сохранённые ранее записи без `textHashes` не получают искусственно восстановленные отпечатки: для них проверка исходного текста не утверждается.

## Проверки и долги

Автоматические: точная цитата / spoofing IDs / некорректный JSON / статус `empty`, отсутствие хранения до подтверждения, запись с provenance, изменение текста, переключение свайпа (включая предка), смена ветки, конфликт во время вызова и отдельный budget.

Зафиксировать реальный prompt/response и bundle SHA. Не сливать в main до отдельного решения.

**Откат:** revert ветки/PR; изменения в базе не происходят без явного нажатия «Сохранить». Новые поля исходного отпечатка — данные, неизвестные старому коду; никакой глобальной миграции старых тестовых чатов не предусмотрено.
