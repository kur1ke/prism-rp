# AUTO-MEMORY-REFLECTION-1 — Memory отдельно от Experience

**Status:** EXPERIMENT; live model partially evaluated in testing (source duplicates reported); source-once fix awaits testing mirror validation. Переопределяет устаревший PR #87. **Base:** `testing`; no changes to `main`.

## Контракт, согласованный 2026-10-26

Пользователь **не вводит, не редактирует, не выбирает и не подтверждает** ни Memory, ни Experience. Взаимодействие — только нормальный Scene/RP или Messenger. Read-only Debug может показать состояние механики. Поле `Core` остаётся шпаргалкой-рекомендацией, не меняется. Важно различать:
- **Memory:** отдельные эпизоды доступного персонажу разговора/отыгрыша с дословным свидетельством и источником. И крупные, и мелкие эпизоды могут сохраниться; память не обязана влиять на характер.
- **Experience:** субъективное осмысление совокупности Memory на основе прежнего Experience и неизменного Core. Может содержать ошибочные убеждения и противоречивые чувства; `unchanged` — допустимый результат. Не переписывает мир и не является командой персонажу.
- **World/Scene:** установленная физическая действительность остаётся независимой от субъективного Experience.

## Реализованный экспериментальный цикл

После успешного сохранения и разбора ответа RP/Messenger запускается отдельный **неблокирующий** цикл:
1. Snapshot нескольких последних сообщений активного пути с полным `id, swipeIdx, textHash, prefixHash` цепочки предков.
2. Короткий LLM-запрос **только по ещё не обработанным источникам** последних четырёх сообщений; не более одного воспоминания на `messageId` (максимум 4 разных источника). При нескольких цитатах из одного сообщения принимается только первое валидное воспоминание. Пустое валидное извлечение отмечает источник как обработанный без создания Memory; при ложной цитате/невалидном JSON — fail closed и без отметки.
3. Берутся 10 последних видимых Memory (новые + сохранённые), **в порядке свежести**, без семантической оценки психологического влияния. Экспериментальные recency веса: 1.0, 0.9, …, 0.1. Старые записи не удаляются из хранилища из-за малого веса.
4. Отдельный LLM-запрос: Core (только рекомендация, данные из Card), previous Experience (если есть), memories + recency. Ответ `changed / unchanged`. В changed — новый короткий текст субъективного взгляда; в unchanged прежний Experience остаётся как был.
5. После валидного извлечения и проверки источника Memory **самостоятельно сохраняется** в `memories`. Ошибка, переполнение или неизменность последующего Reflection не стирают это воспоминание. Новая версия Experience записывается **отдельно**, только если Reflection валиден и что-то изменилось. Каждая запись имеет provenance активного чата/ветки/свайпа; никакой ручной записи.
6. В следующем RP-запросе **последний видимый Experience** подаётся отдельным **опциональным** data-разделом в `Assembler`, рядом с Core, но не входит в Core. При переполнении он может быть исключён; никакого обхода budget.
7. Панель «Память» показывает Memory и Experience **только для чтения**. Ручные Experience buttons/fields и `В опыт` удалены из UI.

### Избирательное извлечение (MEM-SELECTIVE-1)

- Каждое новое сообщение остаётся **кандидатом** для анализа, но не обязано создавать Memory. Extractor получает явные критерии: сохранять конкретные доступные персонажу эпизоды, изменения, новые договорённости и характерные повседневные детали; не создавать запись ради приветствия, пустой реакции или пересказа предыдущей реплики. Возврат `memories: []` — корректный результат.
- Для распознавания повторного упоминания того же события extractor получает не стенограмму, а **не более восьми последних видимых Memory** в виде коротких `event + kind` без `quote` и сырого текста сообщения. Контекст видимости вычисляется из активного пути с учётом swipe и prefixHash. Если budget мал, самые старые элементы этого вспомогательного списка удаляются первыми.
- После ответа модели дополнительно исключаются только **точно совпадающие по нормализованному тексту event** Memory (среди новых событий и последних видимых Memory). Похожесть слов или общая тема не являются основанием объединить два самостоятельных события; более сложная смысловая дедупликация остаётся задачей модели и требует живой проверки.
- Даже если модель не выбрала ни одного события или техническая проверка отклонила повтор, `memorySources` фиксирует обработанные варианты источников; они не анализируются заново после reload. Новые Memory по-прежнему проходят provenance-проверку; Reflection вызывается только если новые Memory сохранены. **Reflection / Experience, Card, Scene и World не меняются.**
- Изменение не гарантирует, что любая модель откажется от банальных Memory, и не обещает идеального различения повторных упоминаний и повторных событий. Проверить на живом RP и Messenger, включая покупки, договорённости, приветствия, возвращения и события в альтернативных ветках.


### Происхождение речи в Memory и Reflection (MEM-SPEAKER-1)

- Обе стороны разговора остаются источниками Memory: персонаж помнит собственные слова и поступки, а также доступные ему сведения от пользователя. Это **не** превращает высказывание в объективный факт о том, кого оно касается.
- `SOURCES.role` уже указывает автора исходной реплики. Extractor должен различать автора высказывания и субъект упоминаемого факта: `character` может рассказывать о своей учёбе, `user` — о своей свадьбе. В `event` субъект события называется однозначно, без смешения биографий.
- При Reflection у каждой Memory в **временном LLM payload** появляется `speaker: "character" | "user" | "unknown"`, восстановленный из сообщения активного пути по `source.messageId`. `quote` и `speaker` позволяют понять, кто сказал «я»; `speaker` не означает, что говорящий сам является субъектом любого третьеличного утверждения.
- Для старых Memory автор восстанавливается таким же способом; изменение структуры коллекций IndexedDB, бэкапов или миграции **не требуется**. Отсутствие канонического сообщения означает `unknown`, а не догадку по тексту.
- `previousExperience` остаётся субъективным, может содержать историческую ошибку атрибуции и не является независимым доказательством. Reflection получает указание не использовать мнения персонажа как доказательство действий пользователя и допускает пересмотр при противоречии источникам.
- Существующие Reflection/Experience **не переписываются задним числом**; исправление влияет на новые осмысления. Не меняются provenance/swipes, Card, Scene, World, модель-хранилище или право пользователя редактировать Memory/Experience (оно по-прежнему отсутствует).
- Живой тест: персонаж сообщает об обучении, пользователь — о свадьбе; следующий Experience должен отличать эти факты. Затем проверить переосмысление ошибочного прежнего Experience после новых Memory, альтернативный swipe, Messenger и `OVERFLOW`. Успешный mock-тест гарантирует формат payload, **не** качество психологической интерпретации реальной модели.

## Границы и ограничения

- Один цикл после ответа; никакого непрерывного моделирования жизни. **В пределах одного чата** автоматические циклы выполняются последовательно в порядке поступления, без пропуска ответа из-за занятого предыдущего запроса. Разные чаты обрабатываются независимо. Если пользователь покинул чат или изменил источник до начала отложенного анализа, цикл корректно завершается как stale без записи.
- При удалении чата или карточки ожидающие циклы помечаются как stale до первого асинхронного обращения к IndexedDB. Если запись Memory/Experience уже была начата, завершившаяся запись удаляется компенсирующей операцией. Тесты с управляемой задержкой хранилища проверяют эти гонки; настоящий IndexedDB остаётся частью ручной проверки браузера.
- Чаты независимы; допустима субъективная ошибка, но не промоутирование Experience в World Truth.
- Аудитория другой ветки не получает память или Experience, если путь до источника отличается; **смена свайпа предка** делает прежний контекст недействительным.
- Текст Core для Reflection готовится тем же `cardContext.core` и с теми же подстановками `{{char}}/{{user}}`, что в Prism. Пользовательский Core не меняется.
- Регрессионные тесты проверяют восстановление обеих коллекций через подставную DB; реальное чтение IndexedDB в браузере пока НЕ ПРОВЕРЕНО. Импорт отклоняет записи с неустановленным владельцем, а UI никогда не переносит статус старого чата в новый.
- Провайдер не вызывается при отсутствии данных или переполнении соответствующего этапа. Сбой Reflection сохраняет уже проверенные Memory, но не записывает неподтверждённый Experience. Нет новых hidden Author Directives из Card/Memory.
- **Ограничение видимости в следующем ходе:** рефлексия асинхронна и не блокирует ввод или генерацию следующего RP-ответа. Если пользователь отправит сообщение раньше её завершения, этот ответ может получить прежний Experience. Следующие сборки Prism получат новую версию после её записи. Требуется отдельная живая проверка задержек/порядка; нельзя утверждать синхронную актуальность.
- Ответ LLM **не может доказать психологическую реалистичность**. Цитата подтверждает происхождение фрагмента, но не истинность пересказа `event`; требуется поведенческий эксперимент.
- Первый эксперимент использует latest 10 memories и не предоставляет семантического извлечения старых эпизодов: это не финальная модель памяти. Не добавляет hardcoded morality/traits.
- **schema v8** добавляет `memorySources` — отдельный журнал успешно проанализированных источников (`chatId`, `owner`, `messageId`, `swipeIdx`, `textHash`, `prefixHash`, уникальный `sourceKey`). Он хранит и пустой результат `[]`; в одной транзакции с новой Memory. Экспорт/импорт проверяют ownership и идентичность, удаление чата/карточки удаляет журнал. Старые `memories` v7 для своего активного источника считаются подтверждением предыдущей обработки. Старые дубли физически не стираются, но в read-only списке и Reflection выбирается только самая ранняя запись из каждого источника. Старые экспериментальные диалоги можно не мигрировать; однако существующие записи не стираются без явной замены базы.
- Старый `experience` store и лексический `prism/experience` остаются как **технический legacy слой** для обратимости и тестов. При активном новом Memory-service старые ручные записи **не подаются** в Prism; новый UI не позволяет их создавать/редактировать. Полное удаление legacy-кода — отдельный следующий этап.
- `process afterReply` завершённый async — не фоновый часовой агент, не произвольный cron.

## Обработка одного источника (AUTO-MEMORY-SOURCE-ONCE-1)

- Одна **вариантная, path-bound реплика** — не более одного Memory. Она определяется активными `messageId / swipeIdx / textHash / prefixHash` и владельцем чата. На другом свайпе или при иной цепочке предков источник отличается и обрабатывается самостоятельно. Все предыдущие канонические записи сохранены.
- После валидного ответа extractor journal отмечает **каждый предложенный для анализа** источник как `memory` либо `empty` в IndexedDB. Повторные запросы не получают ни одного из таких источников: ни при следующем ответе, ни после reload. Старые Memory v7 без журнала также запрещают повторное извлечение своего источника. Ошибка LLM, неверная цитата и preflight overflow **не** фиксируются как успешная обработка, так что возможен повтор на следующем ходе.
- Если сообщение богато несколькими событиями, extractor выбирает **один цельный эпизод**, без превращения каждого предложения в независимую Memory. Разные сообщения могут давать разную память. Отличие от семантической дедупликации: похожие события из реально **разных** источников автоматически не объединяются.
- Старые дубли в одной ветке остаются в базе для обратимости, но read-only Memory/Reflection показывают одну, наиболее раннюю, запись на источник. Это не семантическое удаление и не миграция самих Memory.
- `memorySources` — внутренняя служебная метка работы конвейера, **не команда персонажу и не новая Memory/Experience**. UI не даёт ручного редактирования/подтверждения.

## Критерии для живой проверки

На тестовом Perchance с чистой базой сыграть короткую Scene и Messenger с 1–3 крупными событиями и несколькими бытовыми репликами. Зафиксировать: какие Memory извлечены, не приписаны ли чужие мысли, сколько `changed/unchanged`, как меняется Experience, видит ли RP модель изменённый Experience после нового хода, перестраивается ли интерпретация после разговора. Проверить regen/swipe предка и редактирование источника; отсутствие утечки в другой чат. Попросить модель изменить отношение **только косвенно** новыми событиями, не явными командами. Снять bundle SHA и реальный вывод модели. **CI не заменяет этот эксперимент.** Автоматический CI отдельно проверяет: восстановление после загрузки, расстановку макросов Core, параллельные чаты, смену владельца при импорте, неизменность и целостность рефлексий.

## Rollback

Feature branch / отдельный PR на `testing`, не сливать в `main`. Обновление IndexedDB до **v8** несовместимо с предыдущими v7/v6 клиентами без отдельной миграционной версии или восстановления тестового бэкапа. Старые Memories сохраняются; v7 пустые извлечения неизвестны и, до первого успешного повторного анализа, ещё могут обрабатываться. Не удалять тестовую БД автоматически. Никакого автоматического сброса IndexedDB.
