# AUTO-MEMORY-REFLECTION-1 — Memory отдельно от Experience

**Status:** EXPERIMENT; live model test **NOT RUN**. Переопределяет устаревший PR #87. **Base:** `testing`; no changes to `main`.

## Контракт, согласованный 2026-10-26

Пользователь **не вводит, не редактирует, не выбирает и не подтверждает** ни Memory, ни Experience. Взаимодействие — только нормальный Scene/RP или Messenger. Read-only Debug может показать состояние механики. Поле `Core` остаётся шпаргалкой-рекомендацией, не меняется. Важно различать:
- **Memory:** отдельные эпизоды доступного персонажу разговора/отыгрыша с дословным свидетельством и источником. И крупные, и мелкие эпизоды могут сохраниться; память не обязана влиять на характер.
- **Experience:** субъективное осмысление совокупности Memory на основе прежнего Experience и неизменного Core. Может содержать ошибочные убеждения и противоречивые чувства; `unchanged` — допустимый результат. Не переписывает мир и не является командой персонажу.
- **World/Scene:** установленная физическая действительность остаётся независимой от субъективного Experience.

## Реализованный экспериментальный цикл

После успешного сохранения и разбора ответа RP/Messenger запускается отдельный **неблокирующий** цикл:
1. Snapshot нескольких последних сообщений активного пути с полным `id, swipeIdx, textHash, prefixHash` цепочки предков.
2. Короткий LLM-запрос на 0–3 воспоминания с точным `quote`, `messageId`, `kind`, `event`. При пустом ответе — ничего не писать; при ложной цитате/невалидном JSON — fail closed.
3. Берутся 10 последних видимых Memory (новые + сохранённые), **в порядке свежести**, без семантической оценки психологического влияния. Экспериментальные recency веса: 1.0, 0.9, …, 0.1. Старые записи не удаляются из хранилища из-за малого веса.
4. Отдельный LLM-запрос: Core (только рекомендация, данные из Card), previous Experience (если есть), memories + recency. Ответ `changed / unchanged`. В changed — новый короткий текст субъективного взгляда; в unchanged прежний Experience остаётся как был.
5. После валидного извлечения и проверки источника Memory **самостоятельно сохраняется** в `memories`. Ошибка, переполнение или неизменность последующего Reflection не стирают это воспоминание. Новая версия Experience записывается **отдельно**, только если Reflection валиден и что-то изменилось. Каждая запись имеет provenance активного чата/ветки/свайпа; никакой ручной записи.
6. В следующем RP-запросе **последний видимый Experience** подаётся отдельным **опциональным** data-разделом в `Assembler`, рядом с Core, но не входит в Core. При переполнении он может быть исключён; никакого обхода budget.
7. Панель «Память» показывает Memory и Experience **только для чтения**. Ручные Experience buttons/fields и `В опыт` удалены из UI.

## Границы и ограничения

- Один цикл после ответа; никакого непрерывного моделирования жизни. **В пределах одного чата** автоматические циклы выполняются последовательно в порядке поступления, без пропуска ответа из-за занятого предыдущего запроса. Разные чаты обрабатываются независимо. Если пользователь покинул чат или изменил источник до начала отложенного анализа, цикл корректно завершается как stale без записи.
- При удалении чата или карточки ожидающие циклы помечаются как stale до первого асинхронного обращения к IndexedDB. Если запись Memory/Experience уже была начата, завершившаяся запись удаляется компенсирующей операцией. Тесты с управляемой задержкой хранилища проверяют эти гонки; настоящий IndexedDB остаётся частью ручной проверки браузера.
- Чаты независимы; допустима субъективная ошибка, но не промоутирование Experience в World Truth.
- Аудитория другой ветки не получает память или Experience, если путь до источника отличается; **смена свайпа предка** делает прежний контекст недействительным.
- Текст Core для Reflection готовится тем же `cardContext.core` и с теми же подстановками `{{char}}/{{user}}`, что в Prism. Пользовательский Core не меняется.
- Регрессионные тесты проверяют восстановление обеих коллекций через подставную DB; реальное чтение IndexedDB в браузере пока НЕ ПРОВЕРЕНО. Импорт отклоняет записи с неустановленным владельцем, а UI никогда не переносит статус старого чата в новый.
- Провайдер не вызывается при отсутствии данных или переполнении соответствующего этапа. Сбой Reflection сохраняет уже проверенные Memory, но не записывает неподтверждённый Experience. Нет новых hidden Author Directives из Card/Memory.
- **Ограничение видимости в следующем ходе:** рефлексия асинхронна и не блокирует ввод или генерацию следующего RP-ответа. Если пользователь отправит сообщение раньше её завершения, этот ответ может получить прежний Experience. Следующие сборки Prism получат новую версию после её записи. Требуется отдельная живая проверка задержек/порядка; нельзя утверждать синхронную актуальность.
- Ответ LLM **не может доказать психологическую реалистичность**. Цитата подтверждает происхождение фрагмента, но не истинность пересказа `event`; требуется поведенческий эксперимент.
- Первый эксперимент использует latest 10 memories и не предоставляет семантического извлечения старых эпизодов: это не финальная модель памяти. Не добавляет hardcoded morality/traits.
- Для тестовой базы создана **schema v7** (`memories` и `reflections` с индексом `chatId`). Экспорт/импорт и удаление чата/карточки обновлены. Старые экспериментальные диалоги можно не мигрировать; однако существующие записи не стираются без явной замены базы.
- Старый `experience` store и лексический `prism/experience` остаются как **технический legacy слой** для обратимости и тестов. При активном новом Memory-service старые ручные записи **не подаются** в Prism; новый UI не позволяет их создавать/редактировать. Полное удаление legacy-кода — отдельный следующий этап.
- `process afterReply` завершённый async — не фоновый часовой агент, не произвольный cron.

## Критерии для живой проверки

На тестовом Perchance с чистой базой сыграть короткую Scene и Messenger с 1–3 крупными событиями и несколькими бытовыми репликами. Зафиксировать: какие Memory извлечены, не приписаны ли чужие мысли, сколько `changed/unchanged`, как меняется Experience, видит ли RP модель изменённый Experience после нового хода, перестраивается ли интерпретация после разговора. Проверить regen/swipe предка и редактирование источника; отсутствие утечки в другой чат. Попросить модель изменить отношение **только косвенно** новыми событиями, не явными командами. Снять bundle SHA и реальный вывод модели. **CI не заменяет этот эксперимент.** Автоматический CI отдельно проверяет: восстановление после загрузки, расстановку макросов Core, параллельные чаты, смену владельца при импорте, неизменность и целостность рефлексий.

## Rollback

Feature branch / отдельный PR на `testing`, не сливать в `main`. Новые хранилища сохраняются при откате JS, но старая версия БД v6 не сможет открыть уже обновлённую тестовую БД v7; откат потребует версии приложения, умеющей читать v7, или явного восстановления из предыдущего тестового бэкапа в отдельной тестовой среде. Никакого автоматического сброса IndexedDB.
