# AUTO-MEMORY-REFLECTION-1 — Memory отдельно от Experience

**Status:** EXPERIMENT; live model partially evaluated in testing (source duplicates reported); source-once fix awaits testing mirror validation. Переопределяет устаревший PR #87. **Base:** `testing`; no changes to `main`.

## Контракт, согласованный 2026-10-26

Пользователь **не вводит, не редактирует, не выбирает и не подтверждает** ни Memory, ни Experience. Взаимодействие — только нормальный Scene/RP или Messenger. Read-only Debug может показать состояние механики. Поле `Core` остаётся шпаргалкой-рекомендацией, не меняется. Важно различать:
- **Memory:** отдельные эпизоды доступного персонажу разговора/отыгрыша с дословным свидетельством и источником. И крупные, и мелкие эпизоды могут сохраниться; память не обязана влиять на характер.
- **Experience:** субъективное осмысление совокупности Memory на основе прежнего Experience и неизменного Core. Может содержать ошибочные убеждения и противоречивые чувства; `unchanged` — допустимый результат. Не переписывает мир и не является командой персонажу.
- **World/Scene:** установленная физическая действительность остаётся независимой от субъективного Experience.

## Реализованный экспериментальный цикл

После успешного сохранения и разбора ответа RP/Messenger запускается отдельный **неблокирующий** цикл:
1. Snapshot нескольких последних сообщений активного пути с полным `id, swipeIdx, textHash, prefixHash` цепочки предков.
2. Короткий LLM-запрос **только по ещё не обработанным источникам** последних четырёх сообщений; от 0 до 4 самостоятельных эпизодов за запрос, в том числе несколько из одного `messageId`. Каждый эпизод проходит проверку цитаты; точные нормализованные повторы event отсекаются. Пустое валидное извлечение отмечает источник как обработанный без создания Memory; при ложной цитате/невалидном JSON — fail closed и без отметки.
3. Берутся 10 последних видимых Memory (новые + сохранённые), **в порядке свежести**, без семантической оценки психологического влияния. Экспериментальные recency веса: 1.0, 0.9, …, 0.1. Старые записи не удаляются из хранилища из-за малого веса.
4. Отдельный LLM-запрос: Core (только рекомендация, данные из Card), previous Experience (если есть), memories + recency. Ответ `changed / unchanged`. В changed — новый короткий текст субъективного взгляда; в unchanged прежний Experience остаётся как был.
5. После валидного извлечения и проверки источника Memory **самостоятельно сохраняется** в `memories`. Ошибка, переполнение или неизменность последующего Reflection не стирают это воспоминание. Новая версия Experience записывается **отдельно**, только если Reflection валиден и что-то изменилось. Каждая запись имеет provenance активного чата/ветки/свайпа; никакой ручной записи.
6. В следующем RP-запросе **последний видимый Experience** подаётся отдельным **опциональным** data-разделом в `Assembler`, рядом с Core, но не входит в Core. При переполнении он может быть исключён; никакого обхода budget.
7. Панель «Память» показывает Memory и Experience **только для чтения**. Ручные Experience buttons/fields и `В опыт` удалены из UI.

### Избирательное извлечение (MEM-SELECTIVE-1)

- Каждое новое сообщение остаётся **кандидатом** для анализа, но не обязано создавать Memory. Extractor получает явные критерии: сохранять конкретные доступные персонажу эпизоды, изменения, новые договорённости и характерные повседневные детали; не создавать запись ради приветствия, пустой реакции или пересказа предыдущей реплики. Возврат `memories: []` — корректный результат.
- Для распознавания повторного упоминания того же события extractor получает не стенограмму, а **не более восьми последних видимых Memory** в виде коротких `event + kind` без `quote` и сырого текста сообщения. Контекст видимости вычисляется из активного пути с учётом swipe и prefixHash. Если budget мал, самые старые элементы этого вспомогательного списка удаляются первыми.
- После ответа модели дополнительно исключаются только **точно совпадающие по нормализованному тексту event** Memory (среди новых событий и последних видимых Memory). Похожесть слов или общая тема не являются основанием объединить два самостоятельных события; более сложная смысловая дедупликация остаётся задачей модели и требует живой проверки.
- Даже если модель не выбрала ни одного события или техническая проверка отклонила повтор, `memorySources` фиксирует обработанные варианты источников; они не анализируются заново после reload. Новые Memory по-прежнему проходят provenance-проверку; Reflection вызывается только если новые Memory сохранены. **Reflection / Experience, Card, Scene и World не меняются.**
- Изменение не гарантирует, что любая модель откажется от банальных Memory, и не обещает идеального различения повторных упоминаний и повторных событий. Проверить на живом RP и Messenger, включая покупки, договорённости, приветствия, возвращения и события в альтернативных ветках.


### Происхождение речи в Memory и Reflection (MEM-SPEAKER-1)

- Обе стороны разговора остаются источниками Memory: персонаж помнит собственные слова и поступки, а также доступные ему сведения от пользователя. Это **не** превращает высказывание в объективный факт о том, кого оно касается.
- `SOURCES.role` уже указывает автора исходной реплики. Extractor должен различать автора высказывания и субъект упоминаемого факта: `character` может рассказывать о своей учёбе, `user` — о своей свадьбе. В `event` субъект события называется однозначно, без смешения биографий.
- При Reflection у каждой Memory в **временном LLM payload** появляется `speaker: "character" | "user" | "unknown"`, восстановленный из сообщения активного пути по `source.messageId`. `quote` и `speaker` позволяют понять, кто сказал «я»; `speaker` не означает, что говорящий сам является субъектом любого третьеличного утверждения.
- Для старых Memory автор восстанавливается таким же способом; изменение структуры коллекций IndexedDB, бэкапов или миграции **не требуется**. Отсутствие канонического сообщения означает `unknown`, а не догадку по тексту.
- `previousExperience` остаётся субъективным, может содержать историческую ошибку атрибуции и не является независимым доказательством. Reflection получает указание не использовать мнения персонажа как доказательство действий пользователя и допускает пересмотр при противоречии источникам.
- Существующие Reflection/Experience **не переписываются задним числом**; исправление влияет на новые осмысления. Не меняются provenance/swipes, Card, Scene, World, модель-хранилище или право пользователя редактировать Memory/Experience (оно по-прежнему отсутствует).
- Живой тест: персонаж сообщает об обучении, пользователь — о свадьбе; следующий Experience должен отличать эти факты. Затем проверить переосмысление ошибочного прежнего Experience после новых Memory, альтернативный swipe, Messenger и `OVERFLOW`. Успешный mock-тест гарантирует формат payload, **не** качество психологической интерпретации реальной модели.

### Experience checkpoints из десяток Memory (EXP-CHECKPOINT-1)

- Непрерывная `Memory → Reflection → current Experience` остаётся прежней: каждое новое сохранённое Memory по-прежнему может изменить текущую субъективную перспективу. `current` (старые Reflection без `kind`) — единственный Experience, подаваемый в обычный Prism.
- Отдельно проверяются полные **непересекающиеся группы из 10 Memory**, доступных только по текущему пути чата, с учётом `swipeIdx` и `prefixHash`. Обрабатывается старейшая ещё не завершённая группа. Состав группы — именно 10 конкретных `memoryIds`, не десять последних версий текущего Experience.
- Для группы запускается обычный механизм LLM Reflection с отдельной инструкцией `BATCH_SYSTEM`: `Core + 10 Memory + speaker + recency`, **без** предыдущего/текущего Experience. Это не даёт повторно учитывать одни и те же события внутри группы.
- Checkpoint хранится в существующей коллекции `reflections` как `kind:"batch"` с `memoryIds`, собственным `anchor`, `chatId`, `owner` и `perspective` (или `unchanged` с пустым текстом). Детерминированный ID группы предотвращает повторную запись той же десятки при reload. Новая схема IndexedDB не нужна.
- `batch` не попадает в `currentReflection`, не заменяет последнюю текущую версию Experience и не передаётся в обычный Prism. Этот этап готовит доказуемо раздельные порции для следующей работы по объединению Experience.
- При невалидном ответе, нехватке бюджета или сбое сохранения batch не создаётся; исходные Memory и текущая Reflection остаются. На следующем новом Memory система попробует заполнить незавершённую группу. Не делается скрытых фоновых вызовов, в отличие от текущего post-reply цикла. По-прежнему запрещён ручной ввод Memory/Experience.
- Проверки: 9/10/11 Memory, отказ batch, сохранение после reload, повторная попытка, sibling swipe, изоляция чатов, `OVERFLOW`, запуск `node tests/run.js`, `node tests/test-mirror.js` и `node build.js`. Live Perchance — отдельно.

### Объединение десяти Experience checkpoints (EXP-INTEGRATE-1)

- Когда доступны десять **законченных непересекающихся** `kind:"batch"` из той же ветки и чата, запускается отдельная `INTEGRATE_SYSTEM` Reflection. Отбираются полные группы из 10 checkpoint (то есть до 100 исходных Memory на волну), каждый checkpoint проверяется по всем `memoryIds` относительно активного пути.
- В модель подаются **только десять новых batch Experience** (`change + perspective` без Memory/quote/стенограммы), `Core` и `previousIntegrated` от ранее завершённой волны, если она существует. Поэтому каждое раннее событие попадает в свой batch один раз; старые batch не повторяются в следующей волне. Субъективные заблуждения и противоречия сохраняют право на существование и пересмотр.
- Результат сохраняется в существующий `reflections` store как `kind:"integrated"` с `batchIds`, `previousId`, `anchor` и `perspective`. `unchanged` сохраняет прежний integrated baseline, если он был; пустой итог не подменяет текущий Experience. Схема IndexedDB и бэкап не меняются, ручной ввод запрещён.
- Если integrated привязан к тому же последнему источнику, что и последний `current`, при сборке Prism выбирается **один integrated**. Следующие обычные Reflection получают его как `previousExperience`. В дальнейшем при появлении новых Memory свежий `current` снова становится активным. `batch` никогда не подаётся напрямую в обычный Prism.
- Промежуточные `current`, `batch`, `integrated` сохраняются вместе с provenance. Ни один материал не переносится в Core или World и не смешивается между чатами, альтернативными свайпами и sibling branches. Ошибка дополнительного объединения не отменяет успешные Memory и обычную Reflection; повторная попытка возможна при новом Memory.
- Если объединение было успешно сохранено **позже**, чем более свежий current Experience (например, повтор после сбоя), оно **не перезаписывает** этот более свежий опыт. При следующей непрерывной Reflection добавляется необязательное поле `recentIntegrated`: компактный старший вывод, который модель должна согласовать с более свежим `previousExperience` без дублирования событий. Поле уступает бюджету первым. После успешного обновления текущей Reflection дополнительный материал больше не нужен.
- Регрессии: полный цикл 200 Memory → 20 batch → 2 integrated, отсутствие повторного включения ранних batch во вторую волну, ownership, ancestor swipe, reload/idempotence, строгое ограничение контекста и текущая Reflection. Поведенческий опыт в живой модели оценивается только после тестового деплоя.

### Read-only отображение накопленного опыта (EXP-TIMELINE-UI-1)

- Вкладка «Память» в боковой панели RP и Messenger показывает привычные Memory (до 10 последних) и **один активный** Experience, как ранее. Ниже добавляется блок «Накопленный опыт»: прогресс `Memory → Experience` (0–9/10), прогресс `Experience → общий вывод` (0–9/10), общее число видимых Memory/законченных batch/интеграций, а также раскрывающиеся завершённые порции и история объединений (не более последних 20 в каждом списке).
- Значения **не** считаются по количеству сообщений или всем строкам IndexedDB. `memoryCycle.experienceTimeline` восстанавливает только доступные в активной ветке/свайпе Memory, затем проверяет для каждой десятки точные `memoryIds`, `anchor`, `chatId`, `owner` и `previousId` объединений. Неполные либо чужие группы не показываются; ожидающие Reflection явно отмечаются. `unchanged`-checkpoint отражается без выдуманного текста.
- Вычисление проекции остаётся в чистом доменном модуле; `memoryService.timeline()` предоставляет read-only проекцию, `ui/shell` запрашивает её только при открытой вкладке, а `ui/views/drawer` выполняет только отображение с HTML-экранированием текста LLM. Нет новых полей/слоёв хранения и никакой передачи дополнительных данных в Prism/LLM.
- Все записи Memory и Experience остаются только для чтения: пользователь не вводит и не исправляет их вручную. В мобильном/браузерном тестовом Perchance следует проверить прокрутку, раскрытие истории, уведомления об ожидающих результатах, изменение свайпа и перезагрузку чата. Списки ограничены последними 20 записями для защиты от растущего DOM (более ранние записи остаются в хранилище).

## Границы и ограничения

- Один цикл после ответа; никакого непрерывного моделирования жизни. **В пределах одного чата** автоматические циклы выполняются последовательно в порядке поступления, без пропуска ответа из-за занятого предыдущего запроса. Разные чаты обрабатываются независимо. Если пользователь покинул чат или изменил источник до начала отложенного анализа, цикл корректно завершается как stale без записи.
- При удалении чата или карточки ожидающие циклы помечаются как stale до первого асинхронного обращения к IndexedDB. Если запись Memory/Experience уже была начата, завершившаяся запись удаляется компенсирующей операцией. Тесты с управляемой задержкой хранилища проверяют эти гонки; настоящий IndexedDB остаётся частью ручной проверки браузера.
- Чаты независимы; допустима субъективная ошибка, но не промоутирование Experience в World Truth.
- Аудитория другой ветки не получает память или Experience, если путь до источника отличается; **смена свайпа предка** делает прежний контекст недействительным.
- Текст Core для Reflection готовится тем же `cardContext.core` и с теми же подстановками `{{char}}/{{user}}`, что в Prism. Пользовательский Core не меняется.
- Регрессионные тесты проверяют восстановление обеих коллекций через подставную DB; реальное чтение IndexedDB в браузере пока НЕ ПРОВЕРЕНО. Импорт отклоняет записи с неустановленным владельцем, а UI никогда не переносит статус старого чата в новый.
- Провайдер не вызывается при отсутствии данных или переполнении соответствующего этапа. Сбой Reflection сохраняет уже проверенные Memory, но не записывает неподтверждённый Experience. Нет новых hidden Author Directives из Card/Memory.
- **Ограничение видимости в следующем ходе:** рефлексия асинхронна и не блокирует ввод или генерацию следующего RP-ответа. Если пользователь отправит сообщение раньше её завершения, этот ответ может получить прежний Experience. Следующие сборки Prism получат новую версию после её записи. Требуется отдельная живая проверка задержек/порядка; нельзя утверждать синхронную актуальность.
- Ответ LLM **не может доказать психологическую реалистичность**. Цитата подтверждает происхождение фрагмента, но не истинность пересказа `event`; требуется поведенческий эксперимент.
- Первый эксперимент использует latest 10 memories и не предоставляет семантического извлечения старых эпизодов: это не финальная модель памяти. Не добавляет hardcoded morality/traits.
- **schema v8** добавляет `memorySources` — отдельный журнал успешно проанализированных источников (`chatId`, `owner`, `messageId`, `swipeIdx`, `textHash`, `prefixHash`, уникальный `sourceKey`). Он хранит и пустой результат `[]`; в одной транзакции с новой Memory. Экспорт/импорт проверяют ownership и идентичность, удаление чата/карточки удаляет журнал. Старые `memories` v7 для своего активного источника считаются подтверждением предыдущей обработки. Старые дубли физически не стираются, но в read-only списке и Reflection выбирается самая ранняя запись каждого точного нормализованного event в источнике; разные эпизоды одного источника сохраняются отдельно. Старые экспериментальные диалоги можно не мигрировать; однако существующие записи не стираются без явной замены базы.
- Старый `experience` store и лексический `prism/experience` остаются как **технический legacy слой** для обратимости и тестов. При активном новом Memory-service старые ручные записи **не подаются** в Prism; новый UI не позволяет их создавать/редактировать. Полное удаление legacy-кода — отдельный следующий этап.
- `process afterReply` завершённый async — не фоновый часовой агент, не произвольный cron.

## Обработка одного источника (AUTO-MEMORY-SOURCE-ONCE-1)

- Одна **вариантная, path-bound реплика** — один источник с одной отметкой успешной обработки и, возможно, несколькими Memory. Источник определяется активными `messageId / swipeIdx / textHash / prefixHash` и владельцем чата. На другом свайпе или при иной цепочке предков источник отличается и обрабатывается самостоятельно. Все предыдущие канонические записи сохранены.
- После валидного ответа extractor journal отмечает **каждый предложенный для анализа** источник как `memory` либо `empty` в IndexedDB. Повторные запросы не получают ни одного из таких источников: ни при следующем ответе, ни после reload. Старые Memory v7 без журнала также запрещают повторное извлечение своего источника. Ошибка LLM, неверная цитата и preflight overflow **не** фиксируются как успешная обработка, так что возможен повтор на следующем ходе.
- Если сообщение богато несколькими событиями, extractor может выбрать несколько **самостоятельных эпизодов**, не превращая каждое предложение в Memory. Общий messageId не является дублем события. Похожие случаи не объединяются по общим словам; разные случаи похожего действия должны быть явно различены в event.
- Старые дубли в одной ветке остаются в базе для обратимости, но read-only Memory/Reflection показывают одну, наиболее раннюю, запись на источник. Это не семантическое удаление и не миграция самих Memory.
- `memorySources` — внутренняя служебная метка работы конвейера, **не команда персонажу и не новая Memory/Experience**. UI не даёт ручного редактирования/подтверждения.

## Критерии для живой проверки

На тестовом Perchance с чистой базой сыграть короткую Scene и Messenger с 1–3 крупными событиями и несколькими бытовыми репликами. Зафиксировать: какие Memory извлечены, не приписаны ли чужие мысли, сколько `changed/unchanged`, как меняется Experience, видит ли RP модель изменённый Experience после нового хода, перестраивается ли интерпретация после разговора. Проверить regen/swipe предка и редактирование источника; отсутствие утечки в другой чат. Попросить модель изменить отношение **только косвенно** новыми событиями, не явными командами. Снять bundle SHA и реальный вывод модели. **CI не заменяет этот эксперимент.** Автоматический CI отдельно проверяет: восстановление после загрузки, расстановку макросов Core, параллельные чаты, смену владельца при импорте, неизменность и целостность рефлексий.

## Rollback

Feature branch / отдельный PR на `testing`, не сливать в `main`. Обновление IndexedDB до **v8** несовместимо с предыдущими v7/v6 клиентами без отдельной миграционной версии или восстановления тестового бэкапа. Старые Memories сохраняются; v7 пустые извлечения неизвестны и, до первого успешного повторного анализа, ещё могут обрабатываться. Не удалять тестовую БД автоматически. Никакого автоматического сброса IndexedDB.

## F10 — полное покрытие источника

Extractor получает полный `clean(text)` без прежнего ограничения 900 символов.
Preflight проверяет весь набор источников текущего окна: при нехватке бюджета нет
вызова и отметки успеха. Деление текста и автоматическая обработка всей истории
не добавлены; окно последних четырёх сообщений сохраняется.
Успешные отметки получают `coverage: "full"` вместе с Memory одной транзакцией.
Старые отметки/Memory подтверждают покрытие без повторного разбора только для
очищенного текста длиной не более 900. Длинный источник внутри окна разбирается
целиком; старая отметка обновляется на месте условной транзакцией, чтобы параллельная
вкладка не записала повторный результат. Уже сохранённый эпизод и ссылки Reflection
не переписываются и не дублируются. Несколько самостоятельных эпизодов из одного источника поддерживаются F11.
Отметка означает передачу полного текста анализатору и валидный ответ, а не гарантию
того, что модель запомнит каждое событие. Ошибка, неверная цитата и overflow сохраняют
возможность повтора. Схема IndexedDB v8 и ключи происхождения не меняются; бэкап
сохраняет поле coverage. Живая LLM-проверка F10: NOT RUN.

## F11 — самостоятельные эпизоды вместо ограничения по messageId

Инструкция и parser допускают несколько разных событий в одном сообщении. Общий
предел ответа extractor остаётся 4 эпизода, окно — 4 сообщения, бюджет и лимиты
quote/event не меняются. Полная неверная выдача (включая неверную цитату в одном
эпизоде или превышение лимита) отклоняется без Memory/receipt; частичного успеха нет.
Рефлексия и панель получают до 10 последних эпизодов; checkpoint группирует 10
Memory по ID, а не по числу сообщений. Связь с источником, swipe и prefixHash
сохраняется для каждого эпизода. При одинаковых временных метках порядок стабилен
по ID, чтобы восстановление из IndexedDB не меняло состав групп.

Внутри источника точным дублем считается одинаковый нормализованный event
(регистр, ё/е, пунктуация); другая цитата сама по себе не создаёт новый эпизод.
Разные event могут опираться на одну цитату, описывающую несколько событий.
Пересказы другими словами различает модель с прежним контекстом priorMemories;
детерминированная проверка не пытается угадывать смысл или объединять похожие слова.

Receipt по-прежнему один на источник, все новые Memory и receipt пишутся атомарно.
Уже полностью обработанные сообщения автоматически не пересматриваются. При F10
recovery длинного старого источника сохранённые эпизоды не переписываются, но новый
самостоятельный эпизод может добавиться. Старые записи физически не меняются;
проекция теперь показывает разные event из одного источника. Сохранённые checkpoints
доверяются только при совпадении полного набора memoryIds с текущей проекцией.
Схема IndexedDB v8 и бэкап не меняются. Откат к прежнему коду скроет дополнительные
эпизоды в проекции, хотя записи останутся в базе. Live Perchance/LLM: NOT RUN.

## F13 — ограниченное ожидание модели и восстановление FIFO

Каждый модельный вызов extraction, current Reflection, batch и integration
ограничен 40 секундами. Это предел одного запроса, не всего цикла из нескольких
этапов. `memory-service` передаёт AbortSignal через существующий router в API или
Perchance и отдельно прекращает ожидание через Promise.race. Даже если backend
игнорирует отмену, его позднее завершение не может продолжить просроченный этап,
записать Memory/Experience или изменить статус более свежего цикла. Таймер
снимается при успехе и при ошибке; позднее отклонение Promise также обработано.
Внутренний ctx.memoryTimeoutMs используется для сокращённого дедлайна тестовых
fixtures; пользовательская настройка или запись в базе не добавляется.

Диагностика различает extract-timeout, reflect-timeout, batch-timeout и
integrate-timeout. Последовательная очередь чата освобождается после завершения
неудачного цикла, следующие задачи выполняются по прежнему FIFO. Независимость
чатов и проверки актуальности/удаления/свайпов не меняются. Фоновый повтор не
добавляется; тайм-аут касается модели, не операций хранилища.

- Extraction: ни Memory, ни receipt не записываются, источник остаётся доступным
  для следующего анализа в прежнем окне сообщений.
- Current Reflection: уже успешно записанные Memory и receipts сохраняются;
  не создаётся новая перспектива из просроченного ответа. Следующее новое Memory
  запускает обычную рефлексию с сохранёнными свидетельствами.
- Batch/integration: прежние Memory/current Experience и законченные пакеты
  остаются; просроченный checkpoint/интеграция не записывается. Старейший пропуск
  восстанавливается при следующем новом Memory по прежним правилам группировки.

Тесты: memory-timeout.js — 6 групп, включая уже ожидающую задачу FIFO, повтор,
abort-aware ошибку, проигнорированную отмену, поздние ответ/ошибку, сохранение
успешных этапов и очистку таймеров. e2e-memory-timeout.py — 32 сочетания фаз,
режимов, адаптеров и размеров экрана с настоящей IndexedDB и подменённым внешним
AI/SSE: поздний результат не меняет данные, следующий цикл проходит, reload
восстанавливает те же записи. Live Perchance/LLM — NOT RUN. Схема v8 не меняется.
