# STATE-CONTINUITY-1 — актуальное состояние из текста и авторского DRAW

**Статус:** эксперимент; PR с base `testing`. До ручной проверки живой модели и целевого Perchance-зеркала не объявлять завершённым.

## Проблема

Начальный полный наряд Messenger был корректным событием, но при неполной/неуспешной интерпретации следующих сообщений продолжал представляться как текущий. Авторский DRAW уже был источником частичных wear-событий, но валидатор отвергал полный новый `wear.set`. Для смены наряда приходилось реконструировать отдельные действия над каждой вещью. После выхода последнего DRAW из ограниченного окна старый полный комплект мог снова выдаваться Prism как актуальный.

## Контракт наблюдения

Один авторский ответ может содержать текст, DRAW либо оба источника. Авторский `sw.draws[*].prompt` является повествовательным свидетельством: он **не требует повторного подтверждения текстом персонажа**. Ни последующие переводы, ни переписанный визуальный prompt, ни графическая визуализация не становятся дополнительным источником канона.

Сохраняются три класса наблюдений:

1. **Частичное:** `wear.add/remove/adjust` только для явно обоснованных предметов. Неизображённый предмет не означает снятый.
2. **Полное:** `wear.set` из актуального авторского DRAW, если в **точной цитате** есть однозначный маркер исчерпывающего описания одежды (`на ней только ...`, `wearing only ...` и т.п.) и каждый элемент списка подтверждается той же цитатой. Ни `full body`, ни `selfie` сами по себе не разрешают полный комплект. `wear.clear` допустим только с явным полным отсутствием одежды.
3. **Признанная потеря актуальности:** `wear.invalidate` при явном уже состоявшемся изменении наряда без достоверного текущего полного перечня. Это **не** `wear.remove`, не признание наготы и не создание неописанных событий. Свёртка активной ветки делает актуальный комплект неизвестным; прежние исходные события сохраняются в истории и возвращаются при выборе соответствующего свайпа.

`intent` не может породить `invalidate`. В Messenger подтверждённые сообщения персонажа и DRAW остаются `reported`; излишне сильный `established` модельного кандидата понижается до `reported` до канонического валидатора, не меняя `intent`, actor, источник или цитату.

## Влияние на Prism

`StateResolver` продолжает вычислять контекст из **одного** `StateTracker.fold` для выбранного пути. После `invalidate` отсутствует известный текущий `wear`; никакой старый полный комплект не появляется в `visualWear`. После явного полного DRAW `latestPhotoWear.complete` отличает нынешний установленный наряд от прежней фотографии и удерживает корректную формулировку даже при сокращении опциональных списков по бюджету.

В `StateService` резервный лексический разбор не должен добавлять старые предметы обратно, если основной Observer подтвердил полную замену либо инвалидизацию состояния. Восстановление состояния всегда повторяет события выбранного свайпа, без второго инвентаря и без новых IndexedDB коллекций.

## Инварианты

- Полномочия пользователя и персонажа разделены; только текущий actor.
- `messageId`, `swipeIdx`, `drawIndex`, точная авторская цитата и активная ветка обязательны.
- Ретроспективное изображение, чужой кадр или неавторский DRAW не подтверждают настоящее.
- Никакого удаления вещей только по неполной фотографии.
- `Card`, `Scene`, `Experience`, `World` и исходный характер персонажа не изменяются.
- Бюджет Prism не обходится; из истории не создаётся скрытая стенограмма.
- Существующий persisted `stateEvents` формат расширяется новым action; старые записи остаются совместимыми. `wearState.invalidated` — только производная метка свёртки, не дополнительное хранилище.

## Проверки

Автоматические: `node tests/run.js`, `node tests/test-mirror.js`, `node build.js`. Контрактные тесты: `tests/state-observation-continuity.js`.

Ручная проверка в TEST: исходный полный наряд → авторский DRAW с явно новым полным комплектом без текстового пояснения → 12 обычных сообщений → следующий DRAW; частичный кадр; явное переодевание без перечня; переключение свайпа и возврат; continue с несколькими DRAW; перезагрузка и импорт старого backup. Фиксировать загруженный SHA сборки, ответ Observer, `stateEvents`, итоговый Prism. Никаких заявлений об успешном E2E без фактического запуска.

## Риски

- Языковой маркер «только» иногда относится к видимому фрагменту, а не ко всему наряду; система не должна использовать его без достаточного контекста. Валидатор допускает ограниченные явные выражения, окончательную смысловую интерпретацию делает Observer.
- `invalidate` может чрезмерно часто превращать текущую одежду в неизвестную, если модель неправильно трактует описания. Требуются реальные испытания на длинном диалоге.
- `MAX=6` ограничивает число событий одного сообщения. Если наряд описан как `set`, он занимает одно событие независимо от числа вещей.
- Если Observer не смог извлечь ни одного события, система не должна молча придумывать замену. Отдельная политика для failed/partial в будущих итерациях нуждается в проверке, а не в автоматическом исправлении фактов.
