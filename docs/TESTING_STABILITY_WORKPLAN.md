## Порядок выполнения

Работать последовательно: завершить отдельную задачу, проверить её конечный путь и только затем переходить к следующей. Не объединять все пункты в один большой рефакторинг.

1. **F24 и F25 завершены.** Ожидание ограничено, резерв обновлён и проверен. Для установки обоих исправлений требуется заменить HTML тестового Perchance.
2. **F18 и F23 завершены.** Согласованная активация чатов и экранирование импортируемых HTML-атрибутов проверены в Chromium.
3. **F14 → F15 → F16 → F17 — бюджеты.** Следующий этап. Закрывать каждый путь отдельно; не считать проверку одного сборщика доказательством для всех запросов.
4. **F19 → F20 → F21 → F22 — сохранение и бэкапы.** Инъекции отказов и конкурентных записей, затем reload/restore.
5. **F07 → F08 → F09 — согласованная карточка.** Сначала контракт передачи полей, затем постоянные custom-поля и устранение повторов.
6. **F10 → F11 → F12 → F13 — полнота извлечения и жизненный цикл запросов.** Не вводить новую скрытую систему решений персонажа.
7. **F26 → F27 → F28 → остаток F29 — интерфейс, консультационный контекст, документация и общий E2E.** Новые регрессии по мере исправлений сразу включать в подходящие проверки; этот порядок не откладывает тесты до конца.

## Согласованные требования к карточке — ещё не реализованы

Эти продуктовые требования сохраняются сверх коротких формулировок F07–F09:

- [ ] Возможность заполнить всю карточку и галочками выбрать, какие поля передавать модели.
- [ ] Понятный базовый набор включённых полей по умолчанию.
- [ ] Полный текст выбранных основных полей; не требовать от автора ручного подсчёта символов или составления усечённого ядра.
- [ ] Оценка токенов прямо в карточке; обозначить, что это оценка, если точного токенизатора нет.
- [ ] Цветовые уровни объёма: обычный, жёлтый, красный. Пороговые значения/связь с окном модели ещё требуется определить при реализации.
- [ ] Убрать отдельное поле «Прошлое» как дублирующее лорбук. Не добавлять поддержку неиспользуемого поля ради прежних пользователей; вопрос хранения уже имеющегося текста решить явно, без тихой потери данных.

Не возобновлять незавершённую старую реализацию от main: новая работа выполняется от актуальной testing.
