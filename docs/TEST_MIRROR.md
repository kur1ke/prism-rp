# PRISM — тестовое зеркало Perchance

## Установка один раз
Создайте в Perchance отдельный генератор. В HTML скопируйте содержимое \`dist/perchance/loader-testing.html\`, в Lists — содержимое \`dist/perchance/lists.txt\`. Не меняйте рабочий генератор.
Загрузчик всегда использует ветку \`testing\`, получает её SHA из GitHub API и загружает \`dist/web/prism-app.js\` этого коммита через jsDelivr. Рабочая \`main\` не подгружается даже при сбое.

## Изоляция
Тестовые карточки, переписки, настройки и изображения сохраняются в IndexedDB \`prism-rp-testing\`, а не в рабочей \`prism-rp\`. Публикация GitHub не копирует пользовательскую базу. В тестовом генераторе надо один раз импортировать тестовую карточку или резервную копию.

## Патчи через GitHub
1. Вносите патчи в отдельной ветке и создавайте PR с base=\`testing\`, не \`main\`.
2. При слиянии в testing GitHub Actions запускает \`node tests/run.js\`, \`node tests/test-mirror.js\` и \`node build.js\`.
3. После успешных тестов Actions коммитит обновлённые \`dist/\` в ветку testing.
4. Перезагрузите тестовый Perchance после завершения workflow: загрузчик прочитает новый SHA и загрузит обновлённую сборку.
5. Продакшен обновляется только отдельным согласованным слиянием с \`main\`.

Отдельные .patch-файлы непосредственно в браузере не исполняются: сначала примените их к исходникам в ветке testing, затем запустите сборку. Это позволяет проверять тесты, diff и авторство.

## Ограничения
GitHub Actions должен иметь разрешение Contents: write, а ветка testing должна разрешать коммиты от GitHub Actions. Если это запрещено настройками репозитория, последнюю сборку потребуется обновлять вручную либо настроить разрешения. При недоступности GitHub API загрузчик использует **закреплённый коммит проверенной тестовой сборки**, а не ссылку `@testing`, которую jsDelivr может отдавать из старого кэша (ветки кэшируются до 12 часов). Важно: этот коммит должен использовать **не более старую схему IndexedDB**, чем текущая тестовая база — иначе старый bundle попытается открыть базу v7/v8 как v6 и возникнет `VersionError`. `tests/test-mirror.js` сверяет указанную fallback schema с `DB_VERSION` проекта. Плашка показывает отдельный SHA опубликованного коммита и SHA исходной сборки. Закреплённая версия не обновится автоматически при недоступном API: после новой проверенной публикации резервный SHA надо обновить в `templates/loader-testing.html` и перенести новый HTML в тестовый Perchance. Рабочий `main` никогда не подгружается. Для самого Perchance требуется создать отдельный генератор в аккаунте вручную: GitHub не предоставляет доступа к Perchance-редактору. Проверка Perchance/Forge с живой моделью проводится отдельно.


## Проверенная резервная версия (F25)

Резерв закреплён на опубликованном коммите `dffdad9`, исходная сборка
`1befbc2`, IndexedDB v8. Это версия с единым StateTracker, без старого
Scene-движка и ручного Experience. При отказе API она заменяет прежний резерв
`c92f1c6`; старые скопированные HTML, включая вариант с `9e9cb34`, надо заменить целиком.

Данные проверки находятся в `tests/fixtures/testing-fallback.json`: SHA публикации,
SHA исходников, SHA-256 JavaScript и версия базы. При следующем обновлении резерва
нужно проверить опубликованный bundle на обоих источниках и запуск при отказе API,
обновить manifest и HTML. Тест сверяет их между собой, а не закрепляет старый SHA
как бессрочное правильное значение.

Для проверки скачанного bundle:
`PRISM_FALLBACK_BUNDLE=/path/to/prism-app.js python3 tests/e2e-loader-timeouts.py`.
Сценарий сверяет SHA-256 и исходный SHA, запускает реальный bundle при отказе API,
проверяет тестовую базу и отсутствие старых API.

Ошибка IndexedDB VersionError означает загрузку старого кода. Замените полный
HTML TEST-генератора содержимым `dist/perchance/loader-testing.html`.
**Не удаляйте базу и не очищайте данные браузера** ради исправления загрузчика.

## Ограничение ожидания TEST (F24)

GitHub API получает 5 секунд; затем используется закреплённая резервная версия.
Загрузка JavaScript через jsDelivr получает 20 секунд, затем raw.githubusercontent.com
получает ещё 20 секунд для того же неизменяемого SHA. Срок включает получение
заголовков и чтение тела. При полном зависании сети ошибка появляется примерно
через 45 секунд активного времени страницы; фоновые вкладки браузер может замедлять.

Оба источника должны разрешать CORS: код сначала читается через fetch, затем ровно
один выбранный результат исполняется встроенным script. Тайм-аут отменяет запрос,
а отдельная защита игнорирует поздний результат даже при неудачной отмене.
После начала исполнения резерв не запускается: частично запущенное приложение
не должно получать вторую копию. Ошибка запуска возвращает видимый экран ошибки.

Изменение загрузчика требует заново скопировать полный HTML из
`dist/perchance/loader-testing.html` в TEST Perchance. Обычная перезагрузка
старого скопированного HTML это исправление не устанавливает.
Актуальность закреплённой версии подтверждена для F25 проверкой опубликованного bundle;
при следующих обновлениях одного совпадения версии IndexedDB недостаточно.
