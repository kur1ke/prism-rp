# Единый учёт состояния

Согласовано и реализовано для testing: 3 ноября 2026. Панель «Сцена» — представление состояния, не отдельный движок.

## Владение

`state/tracker.js` — единственный fold физических фактов активной ветки/свайпа. Входы: `stateEvents`, затем `stateCorrections` каждого сообщения; при наличии — типизированная ручная исходная база `chat.initialState` и отдельный начальный наряд Messenger `chat.initialWear`. Эти входы проходят один нормализатор. Отдельного состояния одежды/Scene в базе нет.

- `actors.char` и `actors.user`: location, activity, wear, pose, hair, nearby, ongoing, availability, mood. Для одежды отдельно учитываются worn/removed/partiallyWorn, known/complete и provenance.
- `environment.fields`: явно установленные time, weather, present. Это общая обстановка RP; в Messenger такие события отвергаются. Время — явно установленное значение из текста, без старого календарного парсера и скрытого продвижения часов. Другие имена могут присутствовать в списке present; отдельный физический реестр NPC не добавляется.
- Настроение отображается как интерпретация, не инструкция к поведению. Оно не извлекается из догадок о другом участнике.
- Имена и значения в Prism остаются данными. Имена однострочные, значения — JSON-литералы. События другой ветки/свайпа не входят в текущий fold.

`Tracker.view`, `Tracker.describe`, `Tracker.summary`, `Tracker.wearFacts` только форматируют уже вычисленный snapshot и возвращают копии. Они не сворачивают события повторно и не принимают конкурирующий результат Scene.

## Извлечение: два взаимоисключающих пути одного ответа

По умолчанию `state/service` запускает Observer для текущего текста/авторского DRAW. Модель выбирает фрагмент источника; приложение проверяет точную цитату, actor, certainty и происхождение. Реплики пользователя изменяют только пользователя и явно описанную общую обстановку; ответы персонажа не получают права менять физическое состояние пользователя. Изменение present также не может объявить приход или уход другого основного участника; это проверяется при fold, а не только текстом инструкции.

При включённом экспериментальном State Tool RP-модель записывает `[state: ...]`. Разобранные вызовы сохраняются в том же swipe и переводятся в тот же формат событий. Для ответа с `stateProtocol=1` Observer не запускается, включая ответ без вызовов и Debug retry. Реплики пользователя продолжают проходить Observer. Общие time/weather/present вызовы State Tool допускаются только в RP.

Observer и State Tool — способы получить события, не два движка состояния. Комбинированного `[scene:]` + `[state:]` больше нет.

Авторское первое сообщение нового RP-чата разбирается Observer после открытия чата. Текст/свайпы приветствия сохраняются как авторские; отдельная разметка сцены не требуется. Ожидание последующего хода уже использует существующий pending/settle контракт.

## Потребители

- `prism/service` передаёт актуальный `stateSnapshot` непосредственно `prism/assembler`; контекст и поиск мира получают текущее место из Tracker. `sceneState` больше не вход сборщика.
- Панель «Сцена» и шапка читают тот же snapshot через `Tracker.view`. Старых полей ввода, кнопок переодевания и редактора команд нет.
- Для обычного рисования `images/service` читает Tracker для точного origin path. `Tracker.view`/`wearFacts` дают положение и физические сведения. Место, погода и время RP передаются как контекст. Авторский DRAW сохраняет свой прежний контракт кадра: новые механики не подменяют его содержание старым состоянием и не записывают результат картинки в канон.
- Консультационный ассистент получает сводку RP из Tracker, без независимой свёртки Scene.
- `state/resolver` остался только форматированием удалённых сообщений Messenger и давности reported-сведений. Методов scene/resolve/wearFacts в нём нет; в RP он не участвует.

Неизвестная одежда не означает обнажённость. Пустой комплект показывается как «ничего не надето» только при явно полном пустом состоянии. Частичное наблюдение/снятие не доказывает отсутствие неописанных вещей.

## Удалено без обратной совместимости

Удалены `prism/scene.js`, его подключение, parser `[scene:]`, повторная свёртка, sceneInit/sceneOps/ignoredSceneOps как действующие входы, chat.sceneState/sceneFields/applySceneOps/op, настройка sceneProtocol, метки изменений под сообщениями и ручной редактор Scene. Нет мигратора или адаптера старых команд.

Старые поля сохранённых объектов не конвертируются и не исполняются. Архивный текст не переписывается и база не очищается. Состояние, существовавшее только в старых командах, автоматически не восстановится; новое состояние формируется из новых событий. Это согласованное отсутствие совместимости. Версия IndexedDB остаётся 8, хранилища не меняются.
