# PRISM Unified State Tracker — UT-1 (локальный интеграционный пакет)

**Статус:** прототип интеграции на базе неслитого ST-1 и слитого в main VC-1. В GitHub не отправлен. Живые Perchance, Forge и браузерный E2E **не проверены**. `node tests/run.js`: **273 пройдено, 0 ошибок**; `node build.js`: успешно, 76 скриптов. Текущая метка версии 0.5.0; не объявлять релизом.

## Принцип

Сцена RP и мессенджер — **перспективы взаимодействия с одним состоянием персонажа внутри одного чата**, а не отдельные физические миры. Мессенджер не раскрывает пользователю невидимое автоматически. Переход от независимых чатов к общему World Instance не предусмотрен UT-1: **нельзя объединять старые чаты по одному cardId**.

**Вход:** сохранённые сообщения выбранного пути и свайпа, исторические операции RP `[scene:]`, совместимые legacy-записи среды мессенджера (только начальный слой/ручные исправления), карточка/профиль.

**Выход:** один `StateSnapshot` с `actors.char`, `actors.user` и `scene`; адаптеры `forCharacter`, `forUser` и существующий RP `Scene.describe`. Для изображений используется **снимок по пути до рисуемого сообщения**, включая его события, а не состояние спустя несколько сообщений. Рендер изображения не изменяет канон.

## Контракт события

```json
{
  "actor": "char",
  "field": "wear",
  "action": "set",
  "value": ["белая футболка", "джинсы"],
  "certainty": "reported",
  "evidence": "Я переоделась в белую футболку и джинсы"
}
```

- `actor`: `char` или `user` (канонические роли, не изменчивые написания имён).
- `field`: `location`, `activity`, `wear`, `pose`, `hair`, `nearby`, `ongoing`, `availability`.
- `action`: `set`, `clear`; для одежды `add`/`remove` — по отдельным предметам.
- `certainty`: `established` (явно установленное в RP / пользовательская коррекция), `reported` (утверждение в мессенджере, **не** объективная истина), `intent` (план/намерение, **не** изменение фактического состояния).
- `evidence`: точная подстрока исходного сообщения. Проверяется роль автора, допустимые поля, словесная связь значения с цитатой; неопределённое отклоняется.

**Право на действия:** пользователь задаёт изменения только своего участника; генерирующий персонаж — только свои. В мессенджере обычная реплика не может получить `established`; местоположение, сообщённое персонажем, остаётся `reported`. Исключение — явная пользовательская правка.

## Поток обработки

1. Сообщение пользователя сохраняется в дерево, после чего служебный интерпретатор делает ограниченный вызов текстовой модели (`PRP.llm.simple`), если текст не является простым приветствием. Профиль/секреты других персонажей в вызов не передаются.
2. Модель возвращает кандидаты `events`; модуль проверяет каждый по цитате и полномочиям. Неуспешная интерпретация **не создаёт фактов**.
3. События сохраняются в `swipes[*].stateEvents`. Источник — сообщение, его `id` и активный `swipeIdx`. Результат после переключения чата/ветки или правки текста **не записывается**.
4. Перед ответом, при следующем построении контекста и перед рисованием состояние пересчитывается детерминированно по активному пути. RP-операции `[scene:]` и события из текста применяются в хронологическом порядке.
5. Ответ персонажа после генерации проходит тот же наблюдатель. Директивы RP-модели обрабатываются только в RP. В мессенджере `[scene:]` по-прежнему **неактивны**.
6. Изображение получает `StateSnapshot` на момент сообщения. Установленная одежда не подменяется базовым гардеробом из карточки; картинка не создаёт событие состояния.

## Интерфейс

Обычная переписка/сцена не требует заполнения служебных полей. Во вкладке «Среда» показываются производные сведения; ручная форма скрыта за действием «Ошиблись с состоянием? Исправить…». Исправление в ветке сохраняется в `stateCorrections` выбранного свайпа, а не дублирует отдельную «повседневную» базу. Следующее подтверждённое событие может обновить исправленное поле. Старый `messengerEnvironments.events` остаётся для совместимости с существующими бэкапами и явными глобальными исправлениями.

## Инварианты и границы первого пакета

- Один чат — один независимый мир; никаких угадываемых объединений, новых IndexedDB-коллекций и миграций. Бэкапы старого формата открываются как прежде.
- Карточка и постоянная внешность — отдельный источник, не переписываются случайным текстовым событием, тегами или изображением.
- `intent` не меняет физическое состояние. Утверждение о месте в мессенджере помечается как `reported` и не доказывает истинное местоположение.
- Результат от незавершённого/просроченного наблюдения не может быть применён в другую ветку. При рисовании запрещён запуск изображения для уже сменившегося чата.
- Отсутствие данных **не** означает, что персонаж перестал жить; трекер не придумывает пропущенные события. **Полноценная автономная симуляция вне сообщений остаётся отдельной задачей**, а не скрытым эффектом UT-1.
- Интерпретация потребует дополнительного короткого вызова модели для значимых сообщений и может добавить задержку. Модель может ошибиться: формальные проверки уменьшают риск, но не доказывают корректность в живом диалоге.
- Браузерное E2E и реальные Perchance/Forge тесты **не выполнялись**. Не объявлять готовым к бесконтрольному развёртыванию без живой приёмки.

## Ручная приёмка перед PR

1. Новая переписка без заполнения «Среды»: персонаж говорит «Я дома»; место появляется в диагностике как **сообщённое**, не как наблюдаемая сцена.
2. «Я сейчас переоденусь в пижаму» → намерение, одежда не меняется. «Я уже в пижаме» → обновлённая одежда. Два изображения подряд сохраняют одну установленную одежду.
3. «Я снял куртку» от пользователя не изменяет Орихимэ. При известном гардеробе пользователя снимается только куртка, остальное не придумывается.
4. Открой старую реплику после последующего переодевания: картинка использует прежний снимок.
5. Переключи свайп и верни назад: информация другого варианта не протекает.
6. Отредактируй реплику с установленным состоянием: устаревшее авто-событие исчезает до повторного анализа; явная коррекция пользователя остаётся.
7. Прерви/сломай интерпретатор: диалог остаётся доступным, недоказанные факты не записываются.
8. Проверь Perchance и Forge, скорость дополнительной обработки и бюджет запросов на длительном диалоге.

## Целевой следующий шаг

Реальные тесты событий (самоотчёты, отрицания, цитаты, сложная одежда), защита от долгих тайм-аутов наблюдателя, а затем **отдельное** проектирование разрешённой автономной деятельности вне переписки с привязкой к реальному времени. Не смешивать это с автоматической экстракцией событий из сообщений.
