# PRISM UT-1.5 — безопасность списковых событий

**Цель:** тестовая ветка `testing`, не релиз и не обновление `main`.

## Исходный дефект

При обработке реплик Лилит анализатор иногда сообщал «некорректный список». В текущем трекере многокомпонентному событию одежды было достаточно **одного** совпавшего слова из исходной цитаты, чтобы принять все предметы, включая неупомянутые моделью фантазии. UT-1.4 уже научился понимать буквальное «На мне огромный мягкий свитер ... и тёплые носочки»; UT-1.5 не дублирует это исправление.

## Изменения

- `js/state/tracker.js`: для `wear`, `nearby` и `ongoing` каждый элемент списка отдельно сверяется с точной цитатой. Содержательные слова, которых не было в исходном тексте, приводят к отклонению элемента. Скалярные поля сохраняют ранее принятую проверку.
- `js/state/interpreter.js`: строковые `wear`, `nearby`, `ongoing` приводятся к одноэлементному массиву **только** на границе модельного ответа. Ошибочные объекты, недоказанные значения и неправильные роли остаются отклонёнными. Для `wear.add` можно сохранить только проверенные вещи при ошибке соседнего элемента; `wear.set` с частично неверным комплектом отклоняется целиком.
- Диагностика отклонения указывает номер события и поле, например `Событие 2 [nearby]: некорректный список`.
- `tests/run.js`: дополнительные случаи проверки массива, частичного восстановления, других участников и сквозной фиксации в Messenger.

## Проверки

Локально: `node tests/run.js` — **306 пройдено, 0 ошибок**; `node build.js` — успешно (76 скриптов).

Живое Perchance/Forge и корректность всех свободных описаний одежды пока **не проверены**. Старая переписка автоматически не переобрабатывается: для свежего теста открыть новый диалог с Лилит и проверить описание одежды с двумя предметами.

## Границы

События по-прежнему принадлежат сообщению и варианту; изменения изображений не становятся каноном. Нового фонового процесса, автоматической симуляции вне переписки и ручных обязательных полей этот пакет не добавляет.
