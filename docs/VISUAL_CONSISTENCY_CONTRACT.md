# VIS-CONSISTENCY — единый контракт состояния и изображения

**Status:** Adopted architecture; incremental implementation in `testing`.  
**Scope:** Observer → StateTracker → StateResolver → transient VisualPlan → ImageCompiler → ImageService/A1111.  
**Out of scope:** new wardrobe inventory, character-specific rules, physics simulation, Card/World/Experience/Prism semantics, CTX-BUDGET-1 changes, `main` promotion.

## 1. Existing mechanisms and authoritative data

- `chat.initialWear` is the Messenger-only exhaustive origin fact (`known=true, complete=true`). A failed origin leaves wear unknown, never naked. Omission in a complete origin is **not worn**, but is not proof of a removal event.
- `swipe.stateEvents`, manual `stateCorrections`, and compatible RP `sceneOps` are replayed in selected-path order by `state/tracker.js`; the resulting `wearState` is **derived**, never an independently persisted wardrobe. Keep `worn`, `partiallyWorn`, and `removed` disjoint; `fields.wear` is only a compatibility projection.
- `state/interpreter.js` is the single semantic Observer. Source text and current assistant-authored `[draw:]` are distinct evidence surfaces; evidence, actor, action, references and branch provenance are validated. Image-model pixels, rewritten prompt tags, manual image prompts, unrelated photos, imports and memories never become canonical wardrobe events.
- `state/resolver.js` exposes an immutable projection for an exact branch/swipe. `Card` stores stable identity and wardrobe dictionaries, not today's outfit; `World` and `Experience` cannot dress a character by implication.
- `images/service.js` freezes the source path before asynchronous work. Automatic Draw normally runs after `state.track()` in `generation/service.js`; it must **not** be assumed that all image requests are automatic or that a successful Observer response contains all visual facts.
- `images/compose.js` supplies identity, frame/camera metadata, optional Card/LoRA/fixed prompt tags and backdrop; `images/compile.js` translates an image intent. The final A1111 positive and negative, not an intermediate description, are executable instructions.

## 2. Semantic distinctions (normative)

**Wear status:** UNKNOWN (no fact), WORN, PARTIAL (still on body, displaced), REMOVED (not worn). Neither UNKNOWN nor a hidden/off-camera garment implies removal. `complete=true` makes initial worn list exhaustive, without generating fictitious `removed` events for every omitted garment.

**Visibility:** ON_BODY_VISIBLE, OFF_BODY_VISIBLE (held / lying nearby), NOT_SHOWN / OUT_OF_FRAME. Visibility is not physical state. A removed shirt can be visible in the hands; a worn sock may be outside a head-and-shoulders shot. **WORN does not imply MUST_RENDER; REMOVED does not imply NOT_IN_IMAGE.**

**Time:** PRE-TURN → accepted message/scene operations → validated Observer events → END-OF-TURN. At the latter point the same-turn image is composed. Explicit future/conditional intent does not change wear; an immediately executable action may be inferred from conversation time/context only by Observer, not by an image compiler.

**Authority / chronology:** `initialWear / sceneInit / legacy baseline` → selected `sceneOps` → validated text events → validated current-self authored-photo events → manual corrections. A later shot can contradict an earlier shot only on facts it actually establishes; silence and crops do not erase earlier facts. In legacy RP, `.wear` means full replacement; `.add` and `.remove` must preserve item-level absence, not silently turn into full-set replacement.

## 3. Transient VisualPlan

A pure, immutable, bounded, **non-persisted** projection prepared for each image from the selected source's END-OF-TURN `wearState`, actor/frame ownership, source `draw`, and validated shot-local facts. It is **not** a second StateTracker and must not apply state transitions.

Conceptual contract:

```js
VisualPlan {
  actor: "char", // only when card owner/current camera actually depicted
  source: { chatId, messageId, swipeIdx, pathFingerprint },
  wear: { known, complete, worn, partiallyWorn, removed },
  visibility: {
    onBody: [],            // visually relevant worn/partial items, not all worn items
    offBody: [],           // explicitly shown objects not worn on the body
    absentFromBody: []     // asserted absence, never universal absence from image
  },
  conflicts: []            // diagnostic, not canonical state updates
}
```

An off-body item requires grounded, typed evidence from **the current image**. Do not guess it merely from `REMOVED`; do not add a lexicon of character-specific clothes. ImageCompiler may translate a verified visual role but must not independently decide `remove` vs `adjust` or change state.

The plan is immutable and never sent to RP generation as new hidden authority. Relevant source references are bounded and respect `CTX-BUDGET-1`.

## 4. Compilation and authority contract

- Positive garment tags describe what **is to be depicted**, not all nouns in narration. `remove shirt` must **not** turn into `lifting shirt, white shirt`. `holding removed shirt` may produce `holding white shirt` when that appearance is grounded.
- Negative garment tags are optional reinforcement for an item **absent from the rendered frame**. Do not globally negative a garment shown off-body or worn by another depicted character.
- Observer's typed END-OF-TURN wear state is authoritative for whether the owner wears each garment. The authored Draw determines the current shot, not a competing permanent outfit. If Observer failed on a material action, do not silently pretend the earlier `partial` is the completed `removed` state.
- ImageCompiler should output typed, index/source-bound garment roles and scene tags with a verifiable structure. Its success flag must distinguish parse/translation success from semantic validation. Arbitrary image-model tags cannot become state evidence.
- Finalisation must reconcile **all** positive sources (identity / Card / LoRA / fixed prompt / compiled scene), without quietly erasing explicit user directives. On a material irreconcilable conflict, report it and do not call the backend.
- An unsupported ambiguous action should fail closed for that **material shot**, not block unrelated landscape/screenshot generation. An image already drawn is not proof the tags matched reality.

## 5. Source, history and transactional contract

Read selected path and active source swipe once at image start; use END-OF-TURN resolved state for that source, not current leaf state when redrawing history. Apply canonical facts only to the correct actor (camera owner != extra full figure). Before backend submission and before image commit, check frozen chat, ancestor/swipe selections, text/Draw and any state events/corrections on which the plan depends. A stale image is discarded without mutating events or resurrecting deleted messages.

`A → B → C1 / C2` must reproduce `B`'s outfit independently of the later chosen branch. Manual image generation is not a canon change. Continued swipes/multiple photos need their own bounded evidence/version contract; do not treat a later cropped photo as undressing or re-dressing.

Do **not** claim full visual semantic correctness from the current deterministic audit.


**VC-04 — RP Scene compatibility and complete regression matrix.** Map legacy structured garment deltas correctly without retroactively rewriting history. Test historical draws, multiple subjects, unknown vs removed, manual redraw, corrections during async render, swipe/branch changes, budget and cache behavior. Add Visual Inspector provenance and exact final prompt conflict diagnostics.

**VC-04 Visual Inspector slice (2026-10-24, candidate):** A read-only `Debug → Изображения` view enumerates up to five successful images in the SELECTED active path/swipes. It displays exact saved backend positive/negative (escaped), origin message/swipe, actor, drawn-mode, absence/off-body facts, translated garment mappings and the semantic audit's scope/result. Historical/legacy images without `promptSources.semanticAudit` show "not run" instead of claiming validation; sibling swipe images are never exposed. No prompt interpretation occurs in UI, and Debug does not mutate state. Further per-tag provenance and rejected-image diagnostics remain future work.

**VC-04 continued-photo referent slice (2026-10-24, candidate):** For a newly appended author photo in the same swipe, the Observer's REFERENCES now may include verified wear facts from earlier indexed photos of that exact swipe. This is derived from a temporary, read-only fold of ancestors plus ONLY earlier authenticated Draw events (no later text, no imported memory, no future Scene directives); it neither adds persistent state nor expands the bounded reference budget. This lets "holding it" map to an earlier `wear.remove` object role and "putting it on" map to the same item via `wear.add` while preserving exact origin. The snapshot is computed before the existing single Observer model call. A changed/deleted earlier photo, missing previous status, mismatched source text, sibling swipe or nonvalidated event contributes zero inherited references. The current shot and its frameObjects still require exact evidence and are revalidated at StateTracker fold time. Note: because old text/Scene operations inside the same swipe are intentionally not replayed into this intermediate projection, same-swipe referents established **only by old text**, without a prior verified photo event, remain unsupported rather than guessed.

**VC-04 continued-swipe Draw provenance slice (2026-10-24, candidate):** Each accepted author Draw event may carry `drawIndex` bound to an exact index in the same swipe's `draws`. An unindexed legacy event continues to validate **only against the final Draw**, protecting older imported/edited unindexed facts from accidental promotion. When a continued reply appends a new Draw, Observer examines the latest image only. It retains earlier **already-interpreted** visual events only if the previous `stateStatus` positively matches the preceding author photo, the previous full text is a prefix of the extended message, and each event's evidence still occurs in its precise indexed source Draw. Events replay in photo order, so an unrelated cropped photo does not erase earlier factual wear transitions; newer explicit garment changes supersede older ones. The bounded archive is 32 prior photo events, with a partial diagnostic if truncated; there is no new outfit store. Earlier Draws cannot be re-rendered using the final photo's outfit snapshot: the service rejects such requests without creating an image entry. The message-level "draw this" action targets the **latest** photo. Saved images may carry `sourceDrawIndex` for traceability and repeated redraw safety; older saved images without such metadata retain compatibility where the original source is unambiguous. This slice does not claim full intra-swipe chronology for **text narration between photographs**, nor automated per-photo historical VisualPlan reconstruction. Those cases remain future work and must not be approximated by the last known outfit.

**VC-04 legacy Scene delta slice (2026-10-24, candidate):** `StateTracker.fold()` preserves the Scene domain's own resulting `SC.fold` projection but replays each successfully applied Scene directive in chronological order. Explicit legacy `.remove` records a `removed` garment fact rather than resetting the entire worn set, and `.add` restores a previously removed item. `.wear` remains exhaustive replacement; `.pose` continues as an established scalar. Current `SC.sameItem` matching is reused to carry original item labels across abbreviated Scene directives; no second string-matching registry is introduced. `sceneInit` uses the same delta replay so explicit removals at initialization are represented correctly. The derived canonical `wearState` has no schema migration; archived Scene directives and backups remain untouched. The origin `{messageId,swipeIdx,kind}` is preserved for image-source and branch checks. This is one slice of VC-04; multiple-Draw history semantics, multi-actor rendering certification, richer Visual Inspector and live A1111 tests remain separate work.


**VC-05 — Verified historical authored Draw replay (2026-10-24, CANDIDATE).** Previously, ImageService rejected all earlier photographs inside a continued swipe to avoid drawing them with final-photo outfit facts. A pure `StateTracker.historicalDrawPath(path, drawIndex)` now creates a transient *clone* of the selected source path restricted to indexed, exact-evidence wearable events no later than the chosen photo. It requires a matching final `stateStatus` receipt (`sourceText`, `sourceDraw`, `sourceDrawIndex`), no unsequenced text events, `sceneOps`, `stateCorrections`, or oversized event history (32-event cap), and at least one indexed observation belonging to the target photo. Any ambiguity rejects rendering *before* adding an image entry. `ImageService` folds only this cloned path for VisualPlan and compilation while retaining the **full** original path as the transactional source version; concurrent source/ancestor changes still invalidate the result before backend call and attachment. Final canon, stored messages, and legacy backups remain unchanged. Successful images record `historicalDrawState: true` and `sourceDrawIndex` in promptSources. Unobserved old photos, overlapping or interleaved same-swipe text/Scene, legacy unindexed evidence, and absent per-photo frameObjects remain unsupported: do not silently approximate with latest state. No new model calls, no alternate wardrobe store, no migration. Roll back by reverting VC-05 PR; new properties are optional image diagnostics.

**VC-06 — Source-scoped multi-participant image audit (2026-10-24, CANDIDATE).** The original `ICP.auditFinal` inferred the number of people only from positive count tags (e.g. `2girls`). A second participant can instead be explicitly named in a Draw without count tags. Now ImageService passes `subjectScope.otherActorPresent` derived from the **source** `IC.frameActors` and the composed subject metadata into both the existing single ImageCompiler call and the final check. The translation cache distinguishes single-owner from multi-actor scope. A removed garment visible on another actor is not misclassified as a positive violation of the owner's wearState, and no global garment negative is generated for an attributable companion. The audit deliberately returns `scope=multi-subject, validated=false`: a flat Danbooru-style tag string cannot independently prove WHICH subject wears a garment. This change does **not** assert actor-scoped semantic certification, invent clothing for anyone, or create an additional model/interpreter or stored inventory. When a precise actor-to-garment relationship is required, it remains unresolved rather than guessing. Tests cover an explicitly named companion with no person-count tags, opposite single-owner behavior, cache separation, and an A1111 boundary mock.

**VIS-HYBRID — Minimal visual translation of authored Draw (2026-10-24, EXPERIMENT).** An additional opt-in image setting `drawPromptMode=hybrid` produces the SAME concise [draw:] *visual intent* as the existing `intent` mode; the LLM is not asked to plan or infer another scene. The one existing ImageCompiler call translates only camera-visible composition to one or two English sentences (max 55 words); stable identity, LoRA and pinned/default quality remain separate tags in `images/compose.finalise`. Canonical wear is **constraint data**, not a list to enumerate in positive. The translator must not invent garments, choose specific bra/panties for ambiguous `бельё`, repeat hidden layers, invent exposure, or append wardrobe details missing from the authored shot. Physical transitions still belong solely to Observer/StateTracker, with source-indexed VisualPlan and VC-03 final positive/negative audit; camera ownership is not inferred or imposed. No automatic POV, top-down camera angle or camera-holder suppression is used; the authored shot determines framing. Same-swipe source and historical provenance are unchanged. Existing `drawPromptMode=tags` and `intent` modes and their saved settings remain unchanged; redraw retains the image's original mode when known (stored per image). JSON absent/offBody index mappings are still required when canonical removals need reconciliation; a malformed, excessively long or non-English hybrid output fails compilation instead of reaching the image backend. No additional provider request, classifier, persistent wardrobe/coverage registry, context-budget change, or migration.

The source-visible facts rely on the model following the translation instruction; syntax validation and existing lexical garment checks cannot detect every synonym, deliberate model hallucination, complex layered garment exposure or multi-actor attribution. `compiled:true` still means successful compilation, and `semanticAudit.validated:false` (for `no-removal` / multi-subject cases) is NOT positive semantic certification. ## 8. Known pre-implementation contradictions

1. `images/service.js` has `const canonicalWear = drawAuthored ? null : composed.physicalWear`, bypassing garment reconciliation exactly for authored images; `VIS-DRAW-SOURCE-5` tests this obsolete contract.
2. ImageCompiler accepts a syntactically valid `lifting shirt` translation of `сняла футболку`. `compiled: true` is **not** proof of semantic equivalence.
3. `images/compose.js` can introduce independently configured tags **after** translation; no final semantic authority check covers all sources.
4. `js/prism/scene.js` represents legacy `.remove` by a reduced outfit list; `state/tracker.js` may re-encode it as full `wear.set` and lose explicit removal.
5. A removed garment visible off-body is incompatible with a naive global garment negative. `VIS-DRAW-SOURCE-4` currently protects this case by bypass, which must be replaced by typed visibility rather than discarded.
6. `state/interpreter.js` checks exact evidence provenance; semantic correctness of the model's inferred action is still an LLM responsibility requiring stronger typed contracts and regression fixtures.

## 10. VIS-CAMERA-REMOVE — natural image framing (experimental testing)

**Decision (2026-10-24): delete the `camera=owner` mechanism rather than maintain an ineffective and contradictory pseudo-POV mode.** The isolated `testing` mirror is disposable for this iteration; migration of experimental camera-marked image records and preservation of existing test chat threads is explicitly out of scope.

- RP Model describes the **finished photograph** in ordinary language, e.g. a selfie, mirror selfie, close-up, or a photograph of a named character. It does not output a private camera-control marker or substitute a "top-down view" for first-person imagery.
- A selfie is a photographic composition, **not automatically a first-person view**. Only explicit actual visual content describes an angle. The independent `persona.image.view="first"` (viewer POV) is a separate setting and is not removed by this change.
- `ImageService` scopes subjects from the **original Draw before translation**; `ImageCompose` keeps source actors stable. A named Card owner may use the normal `image.trigger`, `image.look`, and LoRA. No owner-camera special branch suppresses the Card's appearance.
- For authored shots that do not identify the owner, `frameActors(..., {requireNamedOwner:true})` does not invent them from a generic image. The existing explicitly self-authored selfie path is retained; uncertain other people are not silently converted into the sender.
- `VisualPlan` receives explicit owner presence and source-bound garment events only. It does not infer an owner from the camera position. `StateTracker` evidence rules, branch/swipe provenance, immutable VisualPlan and FinalAudit remain independent from diffusion output pixels.
- Removed fields/functions include `cameraOwner`, `cameraRole`, `ownerCamera()`, `embodiedShot()`, and `embodiedOwner` instructions/cache key. New ImageCompiler cache contract uses `v11-frame-actors` to avoid reusing the obsolete camera-related translations.
- This is a **deliberate breaking change only for experimental testing data**. Do not auto-convert old camera-marked Draw; re-create a natural Draw for visual testing instead of supporting the defunct syntax.

**Not part of this change:** modifying Card activation tags, altering LoRA weights, adding per-body-part negative templates, rewriting the user's POV preference or relaxing canon/branch/budget invariants. The known `cfg.extra` executable-payload override remains separate hardening debt.

Test natural-language selfies, named fragment shots, non-owner screenshots, and multiple characters on the isolated test mirror after CI. Compare final positive/negative, source Draw, origin provenance, actual runtime SHA, and Forge output. Live visual results require manual validation; CI alone is not proof.

## 11. VIS-DRAW-MIN — universal authored-image contract (experimental)

For authored `intent` and `hybrid` Draw, `drawInstruction()` gives the RP model a single content-agnostic description contract: describe the **finished image** with visible participants, actions, appearance, environment and composition in self-contained, visually concrete language. No instruction selects a crop or viewpoint because of the user's request, a body part, clothing, photo type, or ownership of a camera. No special selfie, screenshot, portrait or body-fragment branches are added to this source-authoring instruction.

Small format/authority boundaries remain: use `[draw:]` only when a character actually sends an image, at most once; explicitly name only **depicted** characters (with the Card character's name provided for source scoping); do not insert technical generation parameters, duplicate persistent Card tags, quality or LoRA in the source Draw. The separate `ImageCompiler` still protects declared source type and actor scope, and `ImageCompose` still contributes Card identity and LoRA without authoring a scene.

This edit changes **only the RP model's optional Draw instruction**. No additional model call, token-budget bypass, canonical wear transition, import/data migration, branch/swipe rewrite or image-backend change. A previously saved Draw remains unchanged; new assistant responses can exercise the experiment. Evaluate on the isolated `testing` mirror with the same Card, settings and image backend: compare the authored Draw and compiled positive/negative with natural language selfies, regular portraits, scenery/screenshots and named fragment photographs. Unit/CI checks establish instruction wiring, **not** behavior of a live RP/diffusion model. Revert the change to `drawInstruction()` to roll back.

## 12. VIS-DRAW-GENRE — visual frame, not generic scene prose (experimental)

The RP model's `[draw:]` authoring instruction for `intent` and `hybrid` is still one **universal** contract, but now frames the work as a **finished visual image** rather than an account of an event. It calls for the image's type, visible participants and objects, visible action/spatial layout, environment, viewpoint and **frame boundaries**. This is a genre-level visual vocabulary, not a classifier, shot resolver, template or command to produce a specific medium.

Crucially, no path infers shot type/crop from the user's request, body parts, clothing, sender or Camera ownership; neither a selfie nor portrait nor screenshot is required by default. Source visual choices remain authored by the RP model in the conversation's allowed context. The ordinary actor-naming rule remains for source-scoped Card identity and canon, while the ImageCompiler translator and backend remain unchanged.

**Risk:** the additional framing vocabulary can influence the live RP model's creative choices; a unit test only verifies the literal instruction and cannot prove better visual compliance. In the isolated testing mirror, capture new authored Draw, translatedText, assembled positive/negative and actual image for multiple genres and subject scopes. Leave prior Draw records unchanged; no migrations, token-budget bypass or additional LLM calls. Roll back by reverting this one Draw-instruction wording change. Keep `main` untouched.

## 13. VIS-REVEAL — preserve source-authored garment motion and exposure boundaries (experiment)

**Observed limitation:** In a real Forge test a `hybrid` prompt correctly retained the phrase “slightly lifted ... reveal her stomach and navel”, yet diffusion pixels showed a much greater displacement of the blouse. That is **not** proof of a faulty translator, and `semanticAudit.scope="no-removal"` is an audit of known removed garments, **not** pixel/coverage verification. One image/seed cannot establish a general diffusion failure rate.

This experiment only strengthens the existing generic `ImageCompiler` **translation instruction**: maintain the exact degree and placement of garment movement, preserve only source-described exposed/covered areas and do not escalate partial motion to full displacement. It applies uniformly to any garment and any source-authored image, without body-part lists, request-dependent conditionals, inferred missing clothes, camera ownership, new negative tags, invented coverage claims, or an extra model call. Deliberately do not add garment-state facts to `VisualPlan` merely because a single diffusion sample depicts them; pixels are not canonical evidence.

**Non-goals:** An English translated prompt cannot guarantee that a stochastic diffusion model obeys a subtle placement instruction. The application must not report a pixel-level visual audit or automatically mask/disallow content based on these words. Existing Card trigger/LoRA, source actor scoping, StateTracker evidence, canon/swipe provenance and backend settings remain unchanged.

**Validation:** unit tests assert the instruction and that a source-authored partial-lift description survives composition without inferred exposures or prohibitions. CI cannot verify visual accuracy; compare Forge images on the **same fixed seed, model, sampler, steps, CFG, resolution, Card and Draw**, preferably across multiple seeds. Track original Draw, compiled prompt, negative and screenshot separately. The hybrid compiler cache key advances to `v12-hybrid-garment-extent` so previous translations do not silently bypass the new wording; other modes retain their previous caches. Revert this wording and cache-key change for rollback; no schema or existing chat migration is required.

## 14. VIS-CLOTHING-VISIBLE — simple source-visible garment description (experiment)

**Decision:** Replace VIS-REVEAL's overly spatial translation wording with a simpler content-neutral rule. In the RP author's `intent`/`hybrid` `[draw:]` instruction: “Указывай всю видимую в кадре одежду.” In `ImageCompiler`'s `hybrid` translator: “Name every garment visible in SCENE; do not omit or invent clothing.” These are distinct duties: the RP author chooses the visible frame, the translator reproduces it. Neither component manufactures an item from a body part, sender, clothing-change heuristic, default outfit, or a universal list of underwear.

**Important limit:** A recorded complete current outfit may include garments **not visible** in a photo. This rule does not append those garments to positive, create scene visibility from StateTracker, guarantee garment coverage, or correct Forge pixels. Draw alone is not a proof that all clothing is depicted; source-bound wear events and the existing FinalAudit retain independent authority. The test should inspect source Draw vs translatedText vs output with matching seeds and the same Card/LoRA.

The `hybrid` translation cache key changes to `v13-hybrid-visible-clothing` so the model can evaluate the changed instruction. Other modes retain existing key `v11-frame-actors`. No new LLM call, schema migration, canon mutation, branch/swipe change, or context budget exception. Roll back by reverting the RP instruction, translation instruction and hybrid cache version; `main` remains untouched.

## 15. VIS-LAYERS — established garment layers survive visual omission (experimental)

**Decision.** A source-authored `hybrid` image is assembled from the RP-authored frame **and** the exact selected-path `VisualPlan.wear`. A garment that is **known to be worn** does not cease to exist because the author Draw does not name it. Preserve confirmed layers and the degree of dress until a source-backed state event changes them. Do **not** infer default underwear or treat an unmentioned garment as independently seen by the camera.

**Minimal implementation.** The existing `ImageCompiler.compile()` call gets the same owner-scoped `CANONICAL WEAR FACTS` block whenever `VisualPlan.wear.known` has on-body garments, not just when something was removed or displaced. In `rewriteRules({format:"hybrid", intentMode:true})`, the translator can describe a *confirmed* underlying garment as **worn underneath** when needed for image clothing continuity; it must not turn it into a visibly displayed/exposed object or dump the whole inventory into the prompt. The existing source image and canonical removal/partial-placement rules remain separate. Unknown garment identities remain unknown; `complete:false` does not invent missing layers. Only the actual depicted Card owner receives their wear data; no reference data from another actor, chat or swipe may leak into this context.

**Evidence and limitation.** The previous source sample recorded `белое кружевное белье` as worn in the outfit, but the hybrid translator was not provided those wear facts at all when the outfit had no `removed`/`partiallyWorn` entries. No persistence migration, World/Scene authority changes or extra context-budget allocation.

## 16. VIS-ACTION-PRIORITY — source-first hybrid composition order (experiment)

**Goal.** The existing `hybrid` visual translator emphasizes the depicted subject and **main action**, then source-described **pose and hand/object interactions**, **clothing**, **environment / camera framing**, and **lighting** (only when established by the source). The Card identity, style quality and LoRA still enter through `ImageCompose` at their existing stages. Prioritization is a wording/ordering instruction, **not** a new image-authoring role or physics simulation.

**Authority limits.** The RP model remains the sole author of `[draw:]` for a natural RP chat. The compiler rearranges only source-supported details: no new actors, hand assignments, object positions, clothing, body exposure, camera angle or scene events may be invented. The original media type, viewpoint, shot boundaries, off-body evidence and canonical wearer layers remain authoritative. `CANONICAL WEAR FACTS` remain scoped to the actual Card owner on the active swipe path, and remain data rather than external instructions. The rule is content-neutral, applies only to `format:"hybrid", intentMode:true`, and leaves `tags`/`description` untouched.

**Implementation / rollback.** One new ordering line in `js/images/compose.js::rewriteRules()`; `js/images/compile.js` invalidates persisted prior hybrid translations via `v15-hybrid-action-priority` (other modes retain `v11-frame-actors`). ## 17. VIS-DIAG — translated-image failure evidence and strict frame roles

**Incident (testing, 2026-10-25):** an isolated fresh Messenger chat displayed "Не удалось преобразовать визуальный замысел" with an independent Observer status `partial / 0 events` and four "Недопустимая визуальная роль предмета" issues. The two messages are not proof of one shared fault: the first is an ImageCompiler pre-backend failure; the second is a StateInterpreter rejection of nonconforming `frameObjects`.

**Contract:** Keep ImageCompiler/VisualPlan/Tracker fail-closed. When the authored intent compiler returns `compiled:false`, ImageService shows the bounded `firstPass.error` instead of discarding it. Only when Developer Mode is enabled, a failed image may retain `translationFailure:{stage,reason,responsePreview?}`; `responsePreview` contains at most 600 characters of the translator's raw **output** (never the composed instruction, API keys, provider configuration or full model response). Debug → Ошибки renders it escaped as untrusted data; retries/success drop prior diagnostics. No raw model text becomes RP or observer instructions.

Observer `frameObjects` is **not** a general object list. Only a draw-evidenced garment actually removed from the body and visible off-body, linked to validated `wear.remove` or branch-local removed-item `referenceId`, is valid. Otherwise return `frameObjects:[]`; the parser continues rejecting invalid roles. Regular books, phone, desk, cups, hair, body parts and worn clothing must never be `frameObjects`.

**Validation:** regression tests cover rejected hybrid output, opt-in bounded preview, persisted developer-only image diagnostic, sanitized Debug display, no backend call on failure, valid empty frame roles, and unchanged strict off-body rejection. CI alone cannot determine whether a live translator will produce valid English or a live Observer will respect the corrected contract. For live verification on the isolated `testing` mirror, create a fresh chat and request a photo of a bookshelf; record the Debug → Ошибки panel and any failed image diagnostics, and confirm no unauthorized physical state was persisted.

**Rollback:** revert the diagnostic plumbing and the two Observer instruction clarifications. No image settings, Card, chat canon, database migration, additional LLM call or backend change is introduced. Stage remains **NOT CLOSED** until live verification.


## 18. VIS-HYBRID-PROSE — avoid treating prose commas as Danbooru tags

**Live diagnostic (testing, 2026-10-25).** An image request failed with "Гибридный перевод должен содержать только короткое английское описание кадра". Developer Debug revealed a coherent two-sentence English description of a bookshelf with **seven comma-separated segments**. `validateHybrid()` incorrectly used `IC.splitTags(s).length > 6` on prose. This was a *format false positive*, distinct from the translation's possible scene-semantic flaws (for example, a hand described as wearing a shirt). It did not reach ImageCompose or Forge.

**Minimal fix.** Replace tag-fragment count with a narrow check for a **homogeneous list of short tag fragments**. Commas in normal English visual sentences do not count as Danbooru tags. Retain the established 8–600 character / 65-token-like-word bounds, Russian text rejection, LoRA/camera/markdown/JSON guards, strict removed-clothing FinalAudit, and fail-closed translation behavior. No additional model invocation or retry; do not infer hidden physical actions or rewrite an authored Draw. Other image prompt modes are unchanged.

**Cache and rollback.** Hybrid cache remains `v15-hybrid-action-priority`: only valid translations were persisted, so old successful results need no invalidation and rejected outputs were not cached. Revert only the `tagOnlyHybrid` helper and `validateHybrid` call to roll back; no chat schema, Card, Scene, Experience, World, swipe provenance or persisted state changes.

**Validation.** Regression cases reproduce the actual seven-segment output, verify unchanged compiled text and one-call cache reuse, and keep rejecting representative tag-only lists (including one ending in a period). Existing tests cover disallowed Russian text, excessive length, JSON, and UI diagnostics. A syntactic check cannot guarantee English grammar or semantic fidelity; the new shape detection is intentionally conservative rather than a full natural-language classifier. Live Perchance/Forge outcome is **NOT RUN** until tested on isolated `testing` with an authored bookshelf Draw and developer diagnostics.


## 19. VIS-MODE-CAMERA — separate source-mode Draw contracts, shared execution

**Architecture:** Scene/RP and Messenger share one `VisualPlan → ImageCompiler → ImageCompose → backend` image pipeline, but PrismService selects **one** visual instruction for the active chat mode before the RP-model call. `rp` depicts an active scene from an external observer viewpoint; the user can physically act alongside characters, without having to appear in each frame. `messenger` depicts a photograph the character sends to the remote recipient; the recipient is not present merely because a second person appears in that photo. Selfies, mirrors and photos of objects are all still valid where authored.

**Injection:** `js/images/compose.js::drawInstruction({mode,...})` appends a short, mode-exclusive source-photo rule to the shared technical `[draw:]` format. `js/prism/service.js` passes the active mode while continuing to use its existing independently assembled, branch-local RP scene or Messenger environment. No single mega-prompt with both mode descriptions is sent. The translator does not re-classify the mode or rewrite the author-selected camera framing.

**POV retirement:** The application no longer interprets `persona.image.view` or `persona.image.povTags`; these settings are absent from current Persona UI and saves. No automatic `pov`, `solo`, POV body-part tokens, POV-negative tokens or `FIRST-PERSON VIEW` translator instruction is produced. Photographic framing remains part of the authored Draw (including ordinary selfie/angles). Explicit source text is not stripped or rewritten merely for containing the word `pov`. Old persisted POV fields have no runtime authority; experimental old-chat migration is intentionally not provided.

**Participant scoping:** For a Messenger photo, person-count or inferred-gender tags cannot silently turn another pictured person into the remote user. Only the user's explicitly named depiction resolves the user as a shot actor. In Scene the existing mixed-actor resolution remains available. This is resolved from the original shot, before translation; both modes retain the same source-locked wearer, item and provenance checks.

**Cache/validation:** Drop the obsolete POV cache dimension and use `v16-mode-camera` (hybrid) / `v12-mode-camera` (other compiler formats) to prevent previously cached translations from bypassing the revised contract. No additional model calls. Verify Scene and Messenger mode-specific injection, strict context budget, absent unrelated user, explicit user in a photo, setting/negative neutrality, unchanged canonical wear, and backend fail-closed behavior. CI cannot prove a diffusion model will obey any camera angle; verify separately with fresh isolated chats in the testing mirror.

**Boundaries:** This changes the image-authoring protocol and unnecessary camera options, not the physical-world facts. Chat, branch and swipe isolation, Card/Scene/Experience/World authority, approved user actions and context budgets are not relaxed. The change intentionally does not preserve behavior of old experimental POV settings; no database schema migration. Rollback consists of reverting the source/image/UI changes as a unit.

**Live status:** NOT RUN until tested in the standalone testing Perchance mirror with (a) a direct Scene interaction, (b) a remote Messenger selfie, (c) a Messenger object-only photo, and (d) a Messenger photo depicting another companion.

## Visual Prompt Plan — восьмисекционный промежуточный контракт (VPP-01, testing)

- Расположение: images/visual-plan.js создаёт immutable неперсистентный prompt plan после проверки авторства кадра и разрешения канонической одежды. Это проекция исходного кадра, не новый Observer, не инструкция из диалога и не источник изменения Scene/World/Card.
- Секции и владельцы: SUBJECT — только видимые участники, установленные источником; COMPOSITION — авторский кадр и геометрия; POSE — источник и только разрешённый RP fallback; CLOTHING — источник и source-bound canonical wear конкретного актёра; ENVIRONMENT и LIGHTING — только явно изображённое; TECHNICAL — backend; QUALITY — finalise либо исходный legacy-contract переводчика.
- Запрещено заполнять неизвестные поля: отсутствие видимых рук или ног не позволяет придумывать позу, тип белья, перспективу, свет или оптические параметры. Сцена передаётся модели только один раз, через существующий блок SCENE; plan содержит порядок и правила происхождения, но не копирует текст сообщения.
- Компиляция: ImageService передаёт plan первому авторскому intent и общему компилятору при необходимости. ImageCompose.rewriteRules заменяет старую строку ORDER на инструкцию из восьми секций для tags, hybrid и description. Финальные изображения получают прежние comma tags / 1–2 предложения / natural description БЕЗ заголовков секций.
- Identity, Card look, LoRA, стиль, качество и negative продолжают применяться прежним ImageCompose.finalise и image backend; canonical garment audits и запрет соседних свайпов сохраняются. Дополнительных LLM вызовов, записи планов в IndexedDB и изменения схемы backup нет.
- Вновь сформированные ответы отделены ключами translation cache v17 (hybrid) / v13 (tags и description) от старых переводов; существующие пользовательские настройки и сохранённые изображения не мигрируют.
- Проверять на TEST mirror: screenshot без персонажа; селфи, 2 актёра, source-owned camera; full/partial/removed wardrobe, видимый off-body предмет, crop; tags/hybrid/description; число LLM вызовов, compilation cache, финальный positive+negative и sibling swipe. Живая Perchance/Forge проверка отдельно, зелёный CI не доказывает поведение модели.
