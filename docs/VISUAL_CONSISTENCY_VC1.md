# Visual Consistency VC-1 — локальный пакет для проверки

**Назначение:** устранить ложное включение Орихимэ и пользователя в кадр, повторы именных тегов и LoRA, дать переписке собственную сохраняемую визуальную среду без применения физической сцены RP.

**Статус:** локальные изменения, НЕ развёрнуто на GitHub Pages или Perchance; требует проверки на реальных генераторах изображения. Версия PRISM сохранена 0.5.0 до согласования релиза.

## Изменённые участки

- `js/images/compose.js`: чистая функция `frameActors()` определяет владельца карточки и пользователя в конкретном `[draw:]`. Наличие в физической сцене **не означает** наличие в конкретном кадре. Когда источник явно называет только пользователя или другого персонажа, идентификатор и LoRA карточки не добавляются. При отсутствии описания действующих лиц используется осторожный совместимый путь; определения остаются эвристическими. Добавлены алиасы `ё/е`, устранение переставленных именных тегов, дедупликация триггера, сохранение веса LoRA карточки, подсчёт `2girls`, приоритет вручную указанной одежды мессенджера.
- `js/images/service.js`: при генерации картинки из переписки получает визуальную среду из `messengerAt.world` сообщения или разрешает среду для его ветки/времени; строит временное представление **только для изображения**, не пишет сцену RP и не меняет исходную среду. Записывает `promptSources` в запись картинки для диагностики.
- `js/images/compile.js`: кэш перевода учитывает границы участников кадра; версия ключа меняется на `v2-frame`, старые кэши не используются для нового правила.
- `js/messenger/environment.js`: необязательные поля событий среды `visualWear[]`, `visualPose`, `visualHair` (без новой коллекции и версии базы); порядок, время действия и веточные привязки наследуются от прежних событий среды.
- `js/ui/controllers/messenger.js`, `js/ui/views/messenger.js`: ручная установка/очистка визуальных сведений во вкладке «Среда». Пусто — не менять; «очистить» — удалить явно.
- `js/prism/modes.js`: при наличии установленных визуальных сведений передаёт их текстовой модели как **данные** о персонаже вне переписки, не как требования переодеваться.
- `js/ui/views/settings.js`: уточнено значение третьего лица: пользователь появляется только если выбран для кадра, а не по факту присутствия рядом.
- `js/ui/views/chat.js`: раскрывающаяся диагностика источников изображения.
- `tests/run.js`: регрессионные проверки VC-1…VC-10, плюс скорректирован старый тест, который ошибочно требовал добавлять пользователя по одному `1girl, hug`.

## Контракт мессенджера

1. `messengerEnvironment` — это не `RP Scene`. Директивы `[scene:]` в переписке по-прежнему неактивны.
2. `visualWear/visualPose/visualHair` вводятся пользователем; текст и изображения **не перезаписывают их автоматически**.
3. Сообщение хранит `messengerAt.world`; визуализация старого сообщения использует его снимок. Для старых сообщений, у которых визуальных полей в снимке нет, они остаются неизвестными: нельзя подставлять позднейшую одежду даже при совпадающем ручном времени переписки.
4. Карточка остаётся источником базовой внешности. Производное изображение не становится новым фактом.
5. Установленная пользователем одежда в мессенджере имеет приоритет над расходящимися деталями из описания картинки, если в кадре только владелец карточки. Для сложных многоперсонажных кадров фильтрация одежды не применяется, чтобы не удалить одежду другого участника.

## Проверка и развёртывание

Из корня проекта:

```bash
node tests/run.js
node build.js
```

При проверке локально: **243 теста пройдены**; `build.js` создал 73 скрипта. Автоматизированных E2E-тестов в браузере, проверок реального Perchance/Forge, визуального сравнения SD-изображений ещё **не было**. Изменения не применены к удалённому репозиторию.

### Ручные проверки до развёртывания

- Изобразить пустую комнату: в промпте не должно быть триггера или LoRA Орихимэ.
- Изобразить только пользователя: не добавлять внешность Орихимэ.
- Изобразить Орихимэ и пользователя: оба присутствуют, без дублирования имён и чужих черт.
- Промпт с двумя алиасами `orihime_inoue` и `inoue_orihime`: один идентификатор, правильный вес LoRA.
- В переписке задать в «Среде» одежду, позу и причёску; сделать фото; затем изменить одежду и повторно нарисовать старое сообщение — должен действовать снимок **старого** сообщения.
- Проверить переключение веток/свайпов: визуальное изменение одной ветки не проявляется в другой.

### Оставшиеся ограничения и отдельные работы

- Определение состава кадра пока эвристическое; незнакомые имена, неявные действия и сложные групповые изображения требуют явного списка актёров на будущем этапе. Отсутствует полноценный машинный `Actor ID`.
- Автоматическое извлечение изменения одежды из свободного текста диалога не реализовано. Его безопаснее делать как **предложение изменения**, подтверждаемое пользователем, не как прямую запись модели в `messengerEnvironment`.
- Семантические дубли описательных тегов (например, синонимы цвета/причёски) и стабильность фактических пикселей модели не гарантированы.
- `userOverride` из URV по-прежнему не применяется автоматически к профилю пользователя: это отдельная задача импорта.
- Ошибки RP-трекера от неверных `[scene:]` ещё не исправлены. Требуются конкретные примеры неверных обновлений.
- Перед релизом создать резервную копию пользовательской IndexedDB через UI, не очищать данные сайта. Для обратного отката вернуть предыдущий JS-бандл и исходники; старая версия не распознаёт новые поля и может целиком проигнорировать такие события, поэтому перед откатом следует проверить совместимость бэкапа и при необходимости удалить только новые визуальные события на копии данных, не трогая исходные записи.
