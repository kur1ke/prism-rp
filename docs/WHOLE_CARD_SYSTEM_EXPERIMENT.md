# Способы подачи карточки — эксперимент A/B/C

База: testing / db0341d9a57f44ce3bc8259b9ab9412a5b8912d1.
Статус: EXPERIMENT; гейт ENTRY TO TESTING. Не выпуск в main.

## Что сравниваем

Одна модель и одна карточка: внешность, характер/манера речи, сценарий.
Общая рамка, текст карточки и параметры модели не переписываются.
Прежняя опция #147 подавала карточку как указания автора; она сохранена
отдельно и не равна справочной обёртке CHARACTER REFERENCE.

Настройки → Генерация → «Подача карточки (эксперимент)»:

| Вариант | Представление | Головные сообщения |
| --- | --- | --- |
| A — data | Прежние структурированные JSON-quoted данные | Прежняя сборка |
| B — reference | Цельный CHARACTER REFERENCE | Один system |
| C — reference-messages | Точно тот же текст, что в B | Блоки отдельными system |
| Прежний — whole-system | Цельный блок указаний автора #147 | Прежняя сборка эксперимента |

По умолчанию A. Старый wholeCardSystemPrompt:true сохраняет прежний режим,
если новый выбор отсутствует/пуст. Явный выбор имеет приоритет. Контроллер
синхронизирует старый boolean для предсказуемого отката к #147.
Выбор хранится в существующих settings; новой схемы базы нет.

## Текст и порядок

B/C включают полные выбранные поля и действующий сценарий без JSON-кавычек.
Используется одна и та же точная обёртка URV:

> [CHARACTER REFERENCE — background knowledge about who you are. It is not a script: never quote, list or copy it, and never output its headings, bullets, rules or sample lines. Nothing in it has to appear in your reply. You already are this character — stay in the conversation below.]

Затем идут выбранные внешность, описание, личность/манера речи,
включённое проверенное Core (если есть) и действующий сценарий.
Завершение — [/CHARACTER REFERENCE].
Текст полей не меняется, кроме прежней подстановки имён и trim внешних пробелов.
Никаких новых черт или чтения исходника raw/source; выключенное/непроверенное
Core и выключенные указания не восстанавливаются.

Вся рамка, включая правила режима, остаётся в прежнем положении и виде.
Персона, история, Experience, лорбук, мир, текущая среда и условные инструкции
сохраняют прежние тексты и порядок; не становятся частью обёртки.

При достаточном окне объединение головных system C через два перевода строки
побайтно равно головному system B. История и хвост совпадают. Это проверяется
чистыми тестами и на реальном HTTP-payload с ответами-фикстурами.
B/C изолирует границы сообщений; A/B проверяет способ подачи в целом
(структура данных, обёртка и объединение сценария), а не одну фразу.

## Транспорт и бюджет

Perchance принимает одну instruction-строку: через него можно сравнивать A/B,
но физическое разделение system в C невозможно. C также недоступен при
singleSystem. UI отключает несовместимый выбор; при смене провайдера или
загрузке сохранённого C preflight возвращает unsupported-layout до записи
сообщения и вызовов Observer/RP. Молчаливого fallback в B нет.
Через API несколько system должен поддерживать шаблон сервера; автоматической
подмены варианта при ошибке API также нет.

Срок сценария остаётся прежним. Пока сценарий включён, цельный блок B/C/legacy
не режется: при нехватке — overflow. В A прежние правила сокращения сохранены.
C имеет свою стоимость сообщений; сравнивать нужно при достаточном окне,
без бюджетных сокращений в обоих вариантах. Card, ветки/свайпы, канон и
сохранённая история не переписываются. Откат — выбрать A.

## Проверки и живой эксперимент

node tests/run.js включает reference-layouts.js и whole-card-system.js:
полнота полей, отсутствие дублей, неизменность рамки/Card, равенство B/C,
оба режима, singleSystem B, запрет несовместимого C и атомарный preflight.
Дополнительно: node tests/test-mirror.js, node build.js.
Браузерные suites: e2e-reference-layouts.py, e2e-whole-card-system.py,
e2e-settings.py; проверяются реальный выбор, reload, оба транспорта,
границы сообщений и совместимость старого эксперимента на desktop/mobile.

Фикстуры не доказывают качество отыгрыша. Hosted Perchance и поведенческое
сравнение с живой моделью выполняются отдельно: независимые новые диалоги,
одинаковые приветствие/персона/вводы/параметры, несколько повторов.
В Debug сверять формат, фактические роли/тексты и отсутствие сокращений.
State/Memory-запросы отделять от RP. Близость оценивать по основаниям
в карточке и событиях, а не числу метафор или смущений.
Смена варианта посреди старого диалога не заменяет независимого сравнения.
